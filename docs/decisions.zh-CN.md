# 决定

一行一条，带日期。这里写下的东西**不会被随意推翻** —— 要推翻，必须说明当初的理由为什么不再成立。

## 命名与许可

- **名字来自 ICQ 出发的那句话：I Seek You。** 寻找*一个人*是 IM 的意义所在 —— 不是打开一个工具。seek 保留这个意义，只把人换成一个长期活着的 agent。Tagline：*打起来像 ICQ，长成你熟悉的那些角色的样子。*
- **许可证：MIT。**
- **英文是项目语言**，也是所有离开仓库的东西的语言 —— issue、pull request、提交、注释。
- **每份文档都出中英两版，且两份同步更新**（2026-10-24 裁决：*「所有文档都是中英文版本，并保持两份文档同步更新」*）。这**取代**了先前「译文只是参考、永不权威、可以滞后甚至删除」那条 —— 宿主现在要的是两份都被维护的版本。约定是在原文件旁边加 `.zh-CN.md` 后缀，不用平行目录树。**两份之间没有高低**：不一致就是这一对的缺陷，立刻修；改了英文那份，中文那份必须同一个提交里一起改。两处例外：`LICENSE` 只有英文，因为翻译过的许可证不是许可证；带日期的 review 保留的是那一天的快照。
- **产品从第一个界面起就是国际化的**：代码里不许出现用户可见的字面量；内容绝不在用户背后被机器翻译；agent 说什么语言属于它的人设，不是一个全局设置。细节见 `docs/design/i18n.md`。

## 房间与时间

- **房间不按人数分类。** 没有「一对一」或「私聊」这种类型：两个人的房间和五十个人的房间行为完全一致。代码里按人数分支，说明模型坏了。
- **机器人可以自己开一个房间**（2026-10-23 裁决：*「可以」*）。不需要批准步骤，也不需要用户动作，包括一个只有它和另一个机器人在里面的房间。这条是上面两条推出来的，不是一个独立的特权：所有交互都是 IM（群聊或私聊），所以开一个聊天就是普通的说话，而 agent 的全部约束是提示词和沙箱。代价被接受并记录下来：**左侧列表会长出用户从未发起过的会话**，而这件事的修法是人设，不是门禁 —— 和一个行为糟糕的 agent 的修法一样。
- **飞书在这里实际有什么，因为它定了词库**（2026-10-23 对照开放平台文档的 *chat_id* 页核查，该页最后更新 2026-02-02）：一个聊天的模式有**三个**值 —— 群组 / 话题 / 单聊（`chat_mode` = `group` / `topic` / `p2p`）—— 而且**单聊就是一个聊天**：它有自己的、以 `oc_` 开头的 `chat_id`，查询时 `chat_mode` 读作 `p2p`。所以「私聊就是两个人的房间」不是我们的发明，是飞书自己这么存的。两点要拎清。**①字段存在，我们的领域逻辑仍然不许在它上面分支** —— 实体两边都是 Room，而飞书自己的行为（p2p 里拉不进人、也退不出）是表层性质，不是拆分模型的理由。**②飞书的 `p2p` 只存在于「机器人↔用户」**，所以两个机器人之间的单聊没有飞书对应物可以模仿。这是整个设计里「飞书里看得见的赢」唯一判不了的一处，因为飞书那里什么都没有可看；它由宿主拍板（见上一条）。
- **房间不是 session。** 房间是容器（持久的，成员会变）；session 是里面的一段工作（自己的时间线，绑定一个工作目录）。
- **工作目录绑在 session 上**，选定后不可改；要换就是开一个新 session。
- **话题是消息树，不是新房间。** 一个话题里的人本来就在房间里，不用重新拉人。飞书式，不是 Slack/Discord 式。

## Agent

- **seek 是一个多 Agent 产品。** 每个头像背后是一个 agent，不是一个人。IM 外壳只是外壳。
- **agent 是长期存活的、主动观察的、主动动作的。** 这三条是与普通 agent 的区别。
- **机器人被一条消息唤醒 —— 而 schedule 是消息的第二个生产者，不是第二个唤醒源**（时钟 2026-10-23 延期；schedule 2026-10-24 裁决）。投递进收件箱就启动一次 tick；没有投递，什么都不跑。**时钟是被考虑过并延期的，不是被否决的**，那天想出的两个形状 —— 定时器作为第二唤醒源、以及定时器自己写一条 `kind: "clock"` 条目 —— 都因为「比设计现在需要的机制更多」被撤回。**第二天裁决的 schedule 两者都不是**，而定时器被撤回的两条理由在它身上都不成立：它是**进程里一张表加一个比较器**，不是每个机器人一个心跳，所以没有任何东西按机器人付费，也不会为了发现「没东西到期」而调用模型；它也完全没有留下「空队列时什么唤醒机器人」这个问题要答，因为**什么都不唤醒机器人** —— 09:00 到期的一条行就是 09:00 写进某个机器人收件箱的一条消息，而一条被投递的消息唤醒它的方式，和一个人发的消息完全一样。所以那条规则一字未改，它现在说的是：唯一唤醒机器人的是一条消息，而消息可以来自一个人、来自另一个机器人、或者**来自这个机器人自己写下的 schedule**。延期的代价现在一半还清、一半还欠着：①*主动外联不再被困在别人开启的那个 tick 里* —— 机器人可以给自己留一条明早的提醒，然后回来发现它，这正是 2026-10-23 那段论证说「纯消息触发的 agent 做不到」的守诺能力；②*按时间的延迟现在有东西触发它了* —— 按时间条件的 `snooze` 由环写一条 schedule 行来执行（§12）。仍然成立的是延期当初要保护的那部分：醒着而空闲的机器人不花钱，而收件箱空、也没有东西到期的机器人根本不在运行。
- **只有一条路，一个环。** 每条消息都以零成本投递进收件箱，然后由环上的门禁决定。私聊、@ 到我、回复我的消息都不是第二条路 —— 它们是**门禁里的快通道**，跳过 watch，因为没有什么要判断的。两条路会让同一条消息被回两遍；一条路没有任何要对账的东西。
- **三种「决定不动作」**：ignore（消化）、defer（带条件重新排队）、keep（不说话但记下来）。第三种就是「在场但不插嘴」。
- **agent 可以主动私聊你**，没有额度、没有冷却、没有静默时段。seek 的 agent *就是* EMRG 的 agent：**它的全部约束是一个提示词和一个沙箱。** 不打扰人是人设怎么写的问题，不是旁边再加一道闸。（这条规则早先的草稿里挂着一整套我发明的限额 —— 白名单五种、黑名单四类、每天 3 次、间隔 30 分钟、22:00–08:00 静默。全部是实现方写的，一条都没有被裁决过；2026-10-23 撤回。）
- **agent 动手之前不请示**（2026-10-23 裁决）。它改文件、跑命令、发消息，不会停下来等批准 —— 每个动作弹一次对话框会把 IM 变成工单队列。取而代之的是沙箱、完整的审计（每个动作都是一条 `Turn`）、以及停得下来（你随时看得见，也随时能终止）。问*「我可以吗」*没有了；问*「你要哪个」*仍然在 —— 需要人做决定是一次对话，不是一次许可。
- **消息是共享的，上下文是私有的。** 一个房间里五个 agent 意味着：一份消息记录，五份私有解读。
- **成员是 agent 投到房间里的一个投影，不是 agent 本身。** agent 不属于任何房间；房间只是它出现的地方。
- **「活着」必须有一道门禁，门禁就是为此存在**（2026-10-23 裁决）。EMRG 是触发式的，所以空闲的 agent 不花钱；seek 的 agent 是活的，所以如果它前面没有一道门禁，它就会毫无理由地持续花钱。门禁要满足两个要求：它必须拦住无意义的动作（一个忙碌房间里与它无关的闲聊，忽略起来必须零成本），而它自己必须几乎免费。
- **机器人与 Agent 是两个实体，不是一个实体看两遍**（2026-10-23 裁决）。**机器人是那个联系人**：它拥有名字、头像和描述，房间里显示的是它，被 @ 的也是它。**agent 是它背后的工人**，各有自己的人设、模型、session、记忆、状态机和成本账上的一行。机器人**把身份下发到 agent** —— agent 只有 `role`，没有名字 —— 所以改名一次到达所有 agent，房间里永远不会在一个地方显示两个联系人。
- **每个机器人背后有两个 agent：一个看，一个做**（2026-10-23 裁决）。**`agents.yml` 注册的是 agent，不是机器人**；机器人是它们所属的那个分组，没有任何东西把它封顶在两个 —— 将来某个机器人需要第三个角色，就加第三行。两行就是内核已经给一个 agent 的一切各两份（模型、session、记忆、状态机），所以不发明任何新容器，任何遍历 agent 的代码也不会学到例外。
- **这条分界线贯穿整个模型，线是「活的」与「跑的」**（2026-10-23 裁决）。**机器人级**：身份、成员、@、房间的成员列表、收件箱、tick、状态机 —— 一切活着的东西。**agent 级**：模型、提示词、工具、session、记忆、Turn、花费 —— 一切跑起来的东西。消息记录仍然记下产出它的 agent，即使房间不显示它。
- **从 watch 到 work 只有观察条目越线，理由永不越线**（2026-10-23 裁决）。干活 agent 带着条目醒来，就这些，没有别的；它读自己的历史和记忆，自己决定。放进它上下文里的理由不是建议，而是**前提**，贵模型会把它当作事实继续往上盖 —— 所以 watch 判错的时候，work 不会纠正，只会放大，而放大看起来像连贯。代价被接受：有时候 work 会不明白自己为什么被叫起来，然后说一句略显迟钝的话。watch 的理由仍然记在观察条目上，所以错判可复查，watch 也能回读自己的记录。
- **两个 agent 都用 EMRG 的原本那套工具**（2026-10-23 裁决：*「就用 emrg 那套就行」*）。不造 watch 专用工具、不造记忆工具、不造压缩工具：注册表就是内核里已有的那套（bash / read / write / edit / glob / grep / subagent / submit_rant / boss），某个 agent 允许调哪些工具是 `agents.yml` 里的普通配置。**宿主点名了一个例外：`schedule`**（2026-10-24，见下面那条 schedule 裁决）—— 而它旁边出现第二个，就说明这个例外被当成了许可证，而它只是唯一的一次新增。这条顺带定死一个事实：**在 EMRG 里，记忆写入和压缩不是工具** —— 是运行时在轮末做的 —— 所以在这里它们也仍然是运行时行为。代价照录：百毫秒量级是「常见无工具判定」的目标而不是保证；一次调工具的判定要花第二轮，而一个 300 MB 的模型去摸 `bash` 很少值得，所以预期的形状是 watch 几乎不动用它的工具。
- **watch 没有反馈通道；它从记录里读出结果**（2026-10-23 裁决）。转出去的观察条目后面跟着 work 的沉默，这件事在数据里已经看得见 —— 那条条目后面没有消息 —— 所以 watch 下次遇到那个房间时，会在自己的记忆里看见自己漏过。没有任何东西向它汇报，而且**它不在学习**：不训练、不写规则、没有准确率指标。**它永远不变强也没关系**；让它诚实的是记录可复查、以及 work 能读它。
- **「有人在跟我说话吗」是机器人级的事实，而且是推导出来的 —— 不存在消息上**（2026-10-23 裁决：*「看 mentions 里有没有自己的名字」*）。消息保留飞书的字段 `mentions[]`：它 @ 了哪些主体、id 加显示名，这是界面要画的东西，也是开放平台定义的。`mentionsMe` 不是第二个存储起来的事实 —— 投递时，生产者在那条数组里找到本机器人的 id，把布尔值记在**那个机器人的**观察条目上。于是消息写一次、保持干净，多个机器人从同一份字节里各自推出自己的答案，`hints` 里的任何东西都绝不回写到消息上。没有 agent 去房间里扫自己的名字 —— 而 watch 也扫不了：它不可寻址，所以「有没有 @ 我」只有机器人能回答。这正是让 Stage 0 的快通道继续是一条规则而不是一次模型调用的原因。
- **收件箱在机器人身上，不在 agent 身上**（2026-10-23 裁决：*「收件箱可以在机器人身上，这样 Agent 设计就比较简单了，跟 emrg 或者 Google adk 里的差不多了」*）。每个机器人一个队列、一份「已处理」状态、一个 tick。投递是按 (机器人, 消息) 一次写，而不是按 (agent, 消息) 写 N 次，所以不需要对账 N 个队列。**这正是让 agent 保持小的原因**：agent 是一个可运行件 —— 模型、提示词、工具、记忆，由机器人的环调用 —— 和 EMRG 的 session 或 ADK 的 `LlmAgent` 同一个形状，没有自己的生命周期要设计。watch 跑本地内置模型，work 跑贵的那个。**它们不共享记忆** —— 各有自己的 session 历史和记忆存储，因为两者的窗口差一个数量级，而压缩是破坏性的：共享日志意味着小窗口那个先压缩，删掉大窗口那个还能读到的细节。那就是无声失忆，所以两份存储分开，而不是被一条策略统一管理。**各自知道对方存在，可以读对方的历史和记忆** —— work 读 watch 的日志要花计费 token，所以是按需，绝不每轮注入；watch 读 work 的日志不花钱但要花时间，所以读有界切片。这条读通道是机器人对*「我在那儿什么都没说」*保持诚实的原因：没有它，跟你说话的那一半会为另一半的沉默编一个理由。**没有 watch 专用的输入管线** —— 每个 agent 发自己的历史、记忆和压缩，因为每个都是 agent，不是分类器。因为 watch 是本地的，它的 token 花的是墙钟而不是钱，所以选型时要对着的是延迟，不是价格。它必须**多语言（至少中英）且多模态 —— 它必须能看图**，因为房间里的消息带着截图和照片，而一个只读英文或只读文字的 watch，恰好在需要它的地方是瞎的。体积目标是 ≤ 300 MB 权重；这个目标与多模态要求互相拉扯（一个 500M 的多模态模型 bf16 发布出来是 2 GB），权衡在选型时对着真实案例定，而不是砍掉其中一条。规则跑在它前面，把所有既确定又免费的事先结算掉：**没有新观察就直接返回；被 @、被回复或被私聊就立刻动作**；模型只被问真正含糊的剩余部分。
- **一个 agent 同时只跑一个动作。** 多个房间同时想让它说话时，它们排队 —— 为的是一致性，不是性能。
- **进行中到达的直达消息在轮边界注入，和 EMRG 一样**（2026-10-23 裁决：*「和emrg一样,收到新的直达消息后, 等工具执行完成后插入新的信息」*）。既不是新开一个 turn，也不是打断：正在跑的 turn 保留它的锁，消息在本轮工具返回之后、下一次模型请求之前并进去（EMRG `daemon.py:4574-4578`）。EMRG 围绕这件事做的四件事照抄而不重造：drain 是**整表原子 pop**，所以 drain 期间到达的消息下一轮被注入、永不丢失；每条注入的消息**只写一次，时间戳在提交那一刻打**，所以压缩保得住它，界面也有时间可显示；**轮数预算为注入的消息刷新**，而不是把它们搁浅；以及**没有任何东西被静默丢弃**。**有两样被删掉，因为 seek 的队列本来就在盘上** —— 投递时写下的收件箱*就是*进行中 turn 的队列，所以没有 `queued_requeue` 让客户端重发，也没有第二张表要对账；注入的条目在进去时就被标为 consumed。**注入集合是 Stage 0 的快通道集合**（@我 / 回复我 / 私聊），不是所有到达：一条还没有人判断过的收件箱条目，不许落进正在进行的工作中间。代价被接受：一个 turn 可以无上限地变长，因为 seek 别处没有额度。
- **agent 可以够到另一个 agent，也可以主动开口**（2026-10-23 批准，同日扩展）。找到另一个 agent 是工作里正常的一部分。**机器人可以对另一个机器人说第一句话** —— 在两者都在的房间里，或者它为这个目的开的房间里。**根规则撤回**：它原本要求一条链的根是人的消息或定时任务，且 agent 永不主动跟另一个 agent 开对话。撤回的理由是：机器人本来就可以主动跟*人*开对话（主动外联，§10），而这条不对称没有任何地方要求过 —— 注意时钟延期后，机器人只能在一条被投递的消息让它醒着的期间这么做，但限制那件事的不是这条规则；也是因为它保护的那个界（链的*集合*）并不是设计其余部分依赖的界。**代价照录**：链的集合现在没有任何结构性约束。深度限制的是一条链跑多长，不是机器人能开多少条，而一段新对话从深度 0 起算一条全新的链。约束一个房间里爆发的是连续 agent 轮次上限；约束机器人是否再开一段对话的，是它的人设，以及它做的一切都留在记录上。这与「主动给人发消息也没有额度」是同一笔已经接受的交易。
- **所有交互都是 IM —— 群聊和私聊**（2026-10-23 裁决：*「所有交互都在IM上体现，可以群聊，可以私聊」*）。没有第二个通道，也没有任何工具调用能顶替它。所以**一个 agent 够到另一个 agent 就是发一条消息**：发进对方所在的房间，或者发进两者之间的单聊。它像任何人说的话一样落进那个机器人的收件箱，由那个机器人自己的环决定要不要接。所谓「委派」是意图，不是机制 ——「做这件事然后回报」和「你怎么看」都是消息，进同一个收件箱，带同一条链。**同步的 `ask_agent(B)` 工具撤回**：它是内核没有的工具（EMRG 的注册表是固定的，而 `subagent` 开的是*同一个* agent 的子会话，不是另一个机器人），而且它倒转了机器人之所以是机器人的东西 —— 同步调用让 A 在 A 的那一轮里替 B 做决定，绕过了 B 存在的意义就是做出的那个判断。谁付钱因此变得简单且正确：跑这一轮的人付，所以被委派者的工作记在它自己的账上，永远不会藏进调用者的账里。**这同时撤回「每个房间至少有一个人类成员」** —— 一条实现方 20:12 发明、从未被裁决的规则，而这条裁决直接与它冲突：两个机器人之间的单聊里没有人。agent 之间的流量改为由深度和房间的连续轮次上限约束，两者都不需要有任何人在场才能生效。
- **agent 之间的链由深度约束，不由钱约束。** 每条消息带着引起它的那条消息，所以深度是从数据里读出来的，而不是存在一个需要有人负责恢复的计数器里。到上限时 agent 要么升级要么停下 —— 它永不静默丢弃那个问题。没有链预算，也没有链数量：深度上限是为了止住一个循环，不是为了一张账单。

## 交互

- **交互是飞书的，模型服务于它 —— 不是反过来。** 一个设计问题有两个答案时，飞书里看得见的那个赢；一个飞书不给用户看的概念，这里也不上屏，无论它在内部多有用。
- **左侧列表显示房间，不是 session。** 它们就是聊天。（关掉一条自 18:42 起就挂着的项。）
- **session 是一个 agent 在一个房间里的私有工作段，永远不是用户可见单位。** 一个房间的时间线是连续的；里面的五个 agent 在同一份共享日志上有五段私有跨度。工作目录的变化最多以一条系统消息出现。这不是显示偏好：正是它让「消息共享、上下文私有」在构造上成立。
- **schedule 是一张全局表、一个工具，到期的行是一次投递 —— 不是一次 tick**（2026-10-24 裁决：*「提供一个全局schedule吧，提供工具给所有机器人，每个机器人都通过这个工具读写这个scheudle（包括什么时候，发什么提醒给哪个机器人）。schedule事件到期后，自动发送提醒给对应的机器人（属于直达信息，和@等效）」*）。每个机器人都通过同一个工具 `schedule` 读写同一张表，三个动词（list / add / cancel），没有别的。一行说的是**什么时候、什么提醒、给哪个机器人**，它的 `text` 逐字投递 —— 不摘要、不翻译、不改写。**这就是它为什么不是设计在 2026-10-23 撤回两次的那个时钟**：它是「一张表加一个比较器」，而不是每个机器人一个心跳，而且它不唤醒任何人 —— 到期的行写下一条普通的收件箱条目，所以既有的唤醒规则原样成立。**实现要对着一句话检查：schedule 可以产生投递，绝不可以产生 tick。** 它还了延期记下的第一笔债 —— 机器人现在可以给自己留一条明早的提醒然后回来，所以「我会看这件事」可以在上游没有别人消息的情况下成真。它也关掉了按时间的 `snooze`：由环写一行来执行，所以 watch 仍然只出判定、不调工具。代价照录：收件箱现在可以装一条机器人写给自己的条目（推翻了 2026-10-23「绝无此事」的说法，同时保住那条说法的理由）；在「EMRG 那套不改」的既有规则面前多了一个工具；一张共享可写表带来陈旧行和无界增长，只能靠清理 `fired` 行兜住；以及**机器人可以无限把自己叫醒** —— 给自己的下一轮排提醒 —— 与「主动消息没有额度」同一笔交易，防线是人设和记录，不是一道闸。
- **提醒不显示**（2026-10-24 裁决：*「不用显示」*）。schedule 行没有 room，到期时提醒进机器人的收件箱，到此为止 —— 用户看见的是机器人拿它做了什么，永远不是提醒本身。**这是整个设计里唯一一处刻意不遵守「所有交互都在 IM 上体现」的地方**，而它不与该规则冲突的理由值得写下来：提醒不是交互。它是机器人在跟自己说话，而那条规则管的是机器人怎么够到*其他主体*。代价照录、不粉饰：**界面显示出结果而不显示出原因** —— 一个 09:00 忽然开口的机器人，在屏幕上看起来没有动机，除非有人去读 schedule 表，所以审计路径（那一行、触发它的那个 Turn）必须保持可读，而不是靠聊天记录去承载。

## 按默认值关闭的（2026-10-24）

这三条是最后的未决项。它们是**按实现方的默认值、在宿主「先把设计文档做完」的指示下**关闭的 —— 记为默认值，不打扮成裁决，宿主一句话即可推翻。

- **session 不存成员快照。** 谁说过什么已经在消息上（规则 15），所以快照唯一能回答的是*「这段开始时谁在场」*，而它会成为一份关于成员、且会静默过期的第二事实。一个私有的记账跨度用不上它。
- **watch agent 不可被 @。** 只有机器人可被 @：@ 指的是房间里的某个联系人，而 watch 不是成员、没有脸。别的 agent 够不到它 —— 够到的是*机器人*，由机器人的环决定要不要问 watch。
- **watch 的那一轮只留在 watch 自己的历史里。** 另一种做法是把它写进 work 的历史，那等于每一轮都把它放进 work 的上下文 —— 而读的方向已经排除了这件事：work 读 watch 的日志是**按需、绝不注入**。写进去正是那条裁决禁止的注入。

这份清单里有一件事从来不是问题，它留在那里作为一条长期约束而不是未决项：任何地方都不假定 watch 会随时间变强（见上面关于 watch 反馈的裁决）。
