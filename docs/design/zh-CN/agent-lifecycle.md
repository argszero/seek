# 长存活 Agent 设计（seek 内核）

> 宿主 2026-10-23 18:29 定调：**每个机器人是一个完整的 Agent**，与常见 Agent 的区别是三条——
> **长期存活、主动观察、主动动作**。举例：Agent 在某群里，群里有人说话但没 @ 它，这条消息
> 仍然会被送到它手里，它存进自己的「待观察数据」；Agent 内部有一个**主循环**，这是它生命的核心；
> 每一轮先根据观察数据判断**要不要动作**（规则 / 事件 / 便宜模型 / 本地模型 —— 长期存活的 token
> 不能白烧），判断为「要」，才进入真正的 agent 循环；另外它也有「收到消息就处理」的直达方法，
> 用在私聊和 @ 它的时候，与今天 EMRG 的对话一样。
>
> 本文 = 这套 Agent 的设计稿。上层交互（房间、消息、状态感）见 `~/.emrg/designs/seek-mental-model.md`。

---

## 0. 一句话

**一个 Agent = 一份身份 + 一个收件箱 + 一条永远在跑的两段式主循环。**
第一段只花「看得起」的钱决定要不要动，第二段才花「动得起」的钱真的去干。
省钱的全部秘诀在第一段：**绝大多数消息在它这里就该死掉，且死掉的过程一分钱不花。**

---

## 1. 三条通路（先把边界钉死）

| 通路 | 触发 | 花多少钱 | 像什么 |
|---|---|---|---|
| **A 直达** | 私聊 / 被 @ / 被回复它自己的消息 | 完整 agent 循环（工具、全上下文、流式） | 今天的 EMRG 对话 |
| **B 观察** | 房间里有消息，但没点名它 | **零**（只落收件箱） | 人坐在会议室里听着 |
| **C 主循环** | 定时/事件唤醒，看收件箱 | 先廉价判定，命中才付费 | 人决定「这话我得接」 |

A 是「有人叫我」，C 是「我自己觉得该说」。**B 永远不花钱**——这是整套设计的成本地基。
任何实现如果让 B 触发一次模型调用，设计就已经错了。

## 2. Agent 对象

```
Agent
├─ 身份（对外可见，等于 seek 里的一个联系人）
│   id / name / avatar / description   ← description 是给别人（含别的 Agent）判断"该不该找他"的
│   persona                            ← 人设指令：怎么说话
├─ 能力
│   model.main / model.judge           ← 干活用的贵模型 / 判定用的便宜模型
│   tools[] / sandbox / limits
├─ 注意域
│   rooms[]        ← 它在哪些房间里（观察范围）
│   interests[]    ← 关键词 / 话题 / 「谁问我就该答」这类订阅规则
├─ 待观察数据（收件箱，见 §3）
├─ 长时记忆
│   diary（它自己的 markdown 记忆，跨会话、跨房间）
│   roomDigest[room]（每个房间的滚动摘要，给判定器看的廉价上下文）
├─ 生命状态
│   state: 休眠 | 观察 | 判断 | 干活 | 静默(预算耗尽) | 阻塞(等审批)
│   lastSpoke[room] / lastTick / sleepUntil / backoff
│   budget: 每小时/每天 token 上限、已用、重置时刻
└─ 会话
    session[room]（每个房间一个会话；群聊里多人共享，但"它"的上下文是自己的）
```

**关键：Agent ≠ Session。** 今天的 EMRG 把身份压在会话上（会话就是那个 cwd、那个 model、那段历史），
所以一个身份没法同时活在三个房间里。Agent 高于会话，会话是它的一段一段记忆。

> 与宿主 10-23 已下的指令天然接上：`projects.yml` → `agents.yml`，每个 project 就是一个 Agent。
> 那份 `agent-abstraction-step1.md` 是这条线的第一步（把 Agent 抽象出来），本文是第二步
> （给 Agent 装上生命）。

## 3. 待观察数据（收件箱）

一条一条追加，**不做模型处理**：

```json
{ "id": "...", "room": "oc_...", "msg": "om_...", "ts": 1698123456789,
  "sender": "ou_...", "fromAgent": "agent_id|null",
  "kind": "text|image|file|toolcard|system",
  "text": "……",
  "hints": { "mentionsMe": false, "asksQuestion": true, "repliesToMe": false,
             "keywordHit": ["发布", "排期"], "roomTemperature": "busy" },
  "state": "new" }
```

- `hints` 是**生产者打的分**，不是模型打的：@ 检测、问号/疑问词、是否回复我、关键词、消息密度。
  这些全是零成本的字符串/计数运算。
- 状态机：`new → 已判定(act|ignore|snooze|keep) → 消化`；`snooze` 带一个「等到什么时候/什么条件」。
- **容量**：每 (agent, room) 有上限（如 200 条 / 24 小时）。超了不是丢，是塌缩成一行摘要进
  `roomDigest`。否则收件箱会变成第二份消息日志，磁盘与上下文双爆。
- 收件箱只进不出地写，写入方**永不阻塞**（房间扇出不能因为某个 agent 忙而卡住）。

## 4. 主循环：两段式

这是整套设计的核心。伪代码写清楚：

```
每轮 tick:
  ┌ 第 0 段 · 零成本门禁（纯本地计算，不进任何模型）
  │  1. 预算用完？        → state=静默，本轮结束（并对外可见）
  │  2. 冷却期内？        → 除非被 @，本轮结束
  │  3. 收件箱 new 条数=0？→ 加大退避，睡更久，结束
  │  4. 规则命中？（明确 ignore：纯表情/自己发的/别的 bot 的广播/已静音房间）
  │                       → 批量标记 ignore，结束
  │  5. 规则命中？（明确 act：被 @ / 被回复 / 命中「必须应答」订阅）
  │                       → 直接去第 2 段（跳过判定，省钱）
  │  6. 其余 → 进入第 1 段
  │
  ├ 第 1 段 · 廉价判定（一次调用，只看摘要）
  │  输入：唤醒原因 + 该房间最近 N 条的一行摘要 + roomDigest + 我的职责/兴趣
  │        （+ 上次在这个房间说过话是多久之前）
  │  模型：model.judge（本地小模型 / 最便宜的云端模型），无工具，限 max_tokens
  │  输出：严格 JSON —— {"act":0|1, "reason":"<枚举>", "priority":0-3, "focus":["om_..."]}
  │  动作：act=0 → 记 ignore(+reason)，本轮结束（这一步花掉的钱就是全部成本）
  │        act=1 → 进第 2 段，并把 focus 里的消息作为「它决定关注的那几条」
  │
  └ 第 2 段 · 真正的 agent 循环（贵）
     和今天的 EMRG 一轮完全相同：完整上下文 + 工具 + 流式 + 收尾写记忆。
     区别只有两点：① 开头告诉它「你是自己决定要说这句话的，不是被叫的」
                    ② 结束必须写三样：说了什么 / 为什么 / 下次同类情况怎么判
```

### 为什么必须两段

一件事：**判定要看得少，动作要看得全。**
判定器如果读全量历史，它本身就变成了贵模型，省钱的设计当场失效。

### 判定的三种「不动手」

- `ignore`：这事跟我无关。→ 收件箱条目消化掉。
- `snooze`：现在不该说，但之后可能该说（比如问题还没人答、等别人先表态）。
  → 带条件重入队（等 5 分钟 / 等这条被回复 / 等房间安静）。
- `keep`：不用说话，但要**记住**（有人在讨论我负责的模块）→ 写一行进 diary，零动作。

`keep` 这一档很重要：它让 Agent 「在场但不插嘴」，这是长期存活最像人的地方。

### 退避

没事可做时 tick 间隔指数增长（1 分钟 → 8 小时封顶），任何新消息立即打回基线。
EMRG 调度器已有这套（`_heartbeat_interval` = max(i, min(i*8, 8h))），直接复用。
**安静的 Agent 应该几乎不消耗任何东西**——这是「长期存活」能成立的唯一前提。

### 并发

一个 Agent 同时只跑**一个**第 2 段。多个房间同时要动作 → 进 Agent 自己的动作队列，按优先级排：
被 @ > 有人在等回答 > salience 高 > 最久没说话的房间。
理由不是性能，是**身份一致性**：同一个 agent 并行两段对话，它的人设和记忆会打架。

## 5. 成本：算给你看

假设 10 个 Agent、5 个房间、每小时 500 条消息。

| 做法 | 每小时 token | 结果 |
|---|---|---|
| 每条消息都进贵模型（今天的做法，天真移植） | 500 × ~1500 = **75 万** | 一天就破产 |
| 每条只进判定器（不设第 0 段） | 500 × ~300 = **15 万** | 还是贵 |
| **本文设计**：90% 被零成本门禁拦掉，剩 10% 判定，其中 5% 命中动作 | 50 × 300 + 2.5 × 3000 = **≈ 2.3 万** | 可承受 |
| 更省：判定也只在大批量积压时批量跑 | 可再降一个数量级 | 代价是响应变慢 |

（数字是量级估算，不是实测。）

**门禁的命中率就是这个产品的成本曲线。** 所以它必须是**可观测、可调**的：
每个 Agent 记录 `judged`(被判定的批次数)、`acted`(命中数)、`ratio`(命中率)、`spent`(token)。
命中率突然飙到 50%，一定是有人设写歪了或房间被 bot 灌爆了——界面上要直接看得见。

## 6. 与 EMRG 内核怎么接（不重写）

| 组件 | 用今天的什么 | 要新增什么 |
|---|---|---|
| Agent 身份 | `projects.yml` → `agents.yml`（已定） | 上面 §2 的字段 |
| 主循环 | `TaskHandler`（`scheduler.py:982`）：已有心跳、interval/退避、有界周期、stop/trigger/status、重启续跑 | 新任务类型 `agent-tick`，跑 §4 的第 0、1 段 |
| 第 2 段·动作 | 今天的会话一轮（`_run_tool_loop_locked`） | 开场加「你是主动说的」；收尾强制写三样（见 §4） |
| 直达通路 A | 完全不动 | — |
| 观察通路 B | 房间扇出（今天有帧广播，但只发给连着的客户端） | 服务端**扇出到每个成员 Agent 的收件箱**（落盘，不是内存） |
| 判定模型 | `llm.py` 已支持按会话选模型 | 一个「无工具、低 max_tokens、必须返回 JSON」的调用形态 |
| 记忆 | `memory_store` 会话层 + 项目层 | 加 **Agent 层**（跨房间、跨会话、长存） |
| 状态外露 | 帧广播 | 新帧：`agent_state`(观察/判断/干活/休眠/静默) |

**诚实的代价**：今天的 daemon 把「身份 + 运行时」压在同一个 `EmrgServer` 里，
一个进程内多 Agent 并发时，忙表、取消表、上下文都按会话键控，需要按 Agent 再加一层。
这不是不可做，是要认这一层的量。

## 7. 防事故（这类系统真正会死在哪里）

| 事故 | 机制 |
|---|---|
| **两个 bot 互相唤醒，永远聊下去** | ①`fromAgent` 标记：bot 的消息默认**不唤醒**别的 bot，除非被 @ ②每个房间「连续 bot 轮次」上限（grok-bot 定的是 3 轮）③动作后强制冷却 |
| 判定太省 → 又聋又瞎 | 命中率可观测 + 每个 Agent 可单独调阈值 + 「漏掉的」可回看（收件箱保留 ignore 的条目和理由） |
| 判定太贵 → 烧钱 | 预算是一等公民：超了直接 `静默`，并在界面上明确显示（不能让宿主以为它死了） |
| 收件箱膨胀 | 上限 + 塌缩成摘要 |
| 长存活 = 状态腐坏 | 每轮结束写 checkpoint；重启后先自检（预算、队列、上次说话时间）；人设漂移由 diary 校正 |
| 没有时间感 | 每轮注入「你上次在这个房间说话是多久前」「这条消息距今多久」，否则它会反复问同样的问题 |

## 8. 在 seek 界面里必须看得见（否则用户会觉得是 bug）

1. **状态点**：观察中 / 判断中 / 干活中 / 休眠 / 静默。头像角标。
2. **主动消息要有标记**：不是回你的话，是它自己想说的——打一个「主动」标签，否则你会以为它答非所问。
3. **「他为什么没理我」可展开**：把 `reason` 翻成人话（「这条不是问我，且房间里另一个人在答」）。
   这既是产品差异化，也是唯一能调试的手段。
4. **预算可见**：它今天花了多少、还剩多少。

## 9. 分阶段落地

- **P1（最小可活）**：Agent 对象 + 收件箱 + 主循环第 0/1 段 + 单房间 + 规则门禁（无模型判定）。
  此阶段就能看到「它会自己冒一句话」这件事成不成立。
- **P2**：判定器接小模型 + 三种不动手（ignore/snooze/keep）+ 预算与冷却 + 状态帧上界面。
- **P3**：多房间并发与动作队列 + diary 长时记忆 + 命中率面板。
- **P4**：群聊多 Agent（有界轮转、@ 唤醒、(pass) 协议）+ 话题里的委派树。

## 10. 主动私聊（宿主 2026-10-23 18:32 拍板：**能**）

一句「能」把阶梯补全了：**观察 → 房间插话 → 话题 → 私聊 → 必达**。

### 10.1 质变在哪
房间里说话是「在场」，私聊是「找你」。前者的预算单位是 token，**后者的预算单位是打扰次数**。
群里多说是热闹，私聊多是骚扰——所以这一节的全部设计都是围绕「少而准」。

### 10.2 值得私聊的五种情形（白名单，写进人设）

1. **阻塞**：不做决定就没法继续。
2. **已代你办了**：有人问了只有它能答的事，它答了，把原文和结论交给你。
3. **你交代的长期任务有阶段性结论**（不是进度播报，是结论）。
4. **异常**：定时任务失败、预算异常、PR 被打回、CI 红、外部事件。
5. **它自己判断不了又不能靠猜**的问题。

### 10.3 不该私聊的（黑名单）

- 复述房间里刚说过的。
- 「我今天做了 X」这类没有结论的工作汇报。
- 同一件事的第二条（去重键 = 主题 + 房间 + 对象；同一主题走同一条私聊线，续在同一条里，不开新对话）。
- 它在等你回答时再补一条「在吗」。

### 10.4 三道硬闸

| 闸 | 默认值 | 说明 |
|---|---|---|
| 每天上限 | 3 次 | 「阻塞」类不占额度，但每天最多 1 次 |
| 最小间隔 | 30 分钟 | 两条主动私聊之间的距离 |
| 静默时段 | 22:00–08:00 | 阻塞类也只发一条，且明说「可以明天再看」 |

额度用尽 → 降级为房间留言，状态照旧可见（你翻房间能看到它想说但没打扰你）。

### 10.5 打扰了却没人理

- 未回答的私聊标 `unanswered`，**同一主题不再追发**。
- 连续 3 条 `unanswered` → 这个 Agent 自己的主动私聊频率自动减半（自适应降噪）；你回一次即恢复原频率。
- 绝不「再问一次确认」。没回应是信息，不是拒绝，它该继续干活。

### 10.6 说可以自由，做必须先问

**主动说**不需要批准；**主动做**——任何有副作用的动作（以你的名义给别人发消息、改文件、跑命令、花钱）——一律先问。
这条线比沙箱档位更靠前，因为它保护的不是文件，是「你不知道它在替你做什么」。

### 10.7 界面上

- 主动私聊的消息带「主动」标记，**并且必须带一行理由**（「你交给我的那个任务刚刚失败了」）。没有理由不许发——理由行是硬性要求，也是你事后判断它靠不靠谱的唯一依据。
- 联系人列表显示「有 1 条主动消息」。
- 它发完不等你：界面要能表达「我先自己继续，你回头再看」。
