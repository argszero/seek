# 国际化

> 项目面向国际；英文是主要语言。这份文档讲的是**产品**——界面和它的数据——不是仓库的语言政策（那在 `CONTRIBUTING.md`）。

---

## 1. 决定其余一切的那条规则

**代码里不写任何用户可见的字符串。** 每一个标签、提示、空状态、错误和浮层提示，都在渲染时按键查出来。组件文件里出现字面量就是 bug，和写死一个颜色是同一种 bug。

原型违反这一条：约 7900 个中日韩字符的界面文案内联在 `src/js/` 里。它是存档，不会回头补；实现必须从第一屏就做对，因为以后回头补，代价比一开始就做对高得多。

## 2. 两种语言，不是一种语言加译文

| | 界面语言 | 内容语言 |
|---|---|---|
| 是什么 | 外壳：菜单、按钮、标签、系统通知、格式化 | 人和 agent 打出来的东西 |
| 谁拥有 | 应用 | 参与者 |
| 怎么改 | 一个设置；立刻生效 | 永不重写，永不自动翻译 |

**内容绝不在用户背后被机器翻译。** 用户想把某条消息翻过来，是对那条消息的一次显式动作，并且标成译文。悄悄改写别人说过的话是信任上的越界；在一个 agent 会说话的产品里，它还会让人分不清 agent 到底说了什么。

**反方向不是同一条规矩。***进程*说的东西——一个状态码、`fetch failed`、某台主机吐的五个字——是诊断而不是内容，所以它也从不搬到屏幕上：失败由窗口用它正在说的那种语言说，诊断进日志（`docs/host-rulings.md`「窗口不把用户当开发人员」）。人写的字是内容，保持在它被写下时的样子；进程写的字是诊断，留在开发者会去看的地方。这不是一条规矩的两半，而是两条方向相反的规矩，界线就是这句话是谁写的。

## 3. 一个 agent 说什么语言

agent 的语言是它**人设**的一部分，不是一个全局设置：

- `persona` 可以钉死一种语言（「用英文回答」），也可以跟着跟它说话的那个人走（默认）。
- 一个在观察房间的 agent，应该随这个房间的主流语言，而不是强推自己的。
- agent 配置的语言和用户的界面语言不同，是正常而预期的——它是个人，不是外壳。
- 所以群聊可以混语言。模型里没有任何东西需要在意这一点；消息就带着它带着的那段文字。

## 4. 受区域影响的格式化

下面所有东西都走同一层格式化，按 locale 取，绝不在调用处拼字符串：

| 值 | 说明 |
|---|---|
| 时刻 | 24 小时制还是 12 小时制是 locale 的决定，不是品味的决定 |
| 相对时间（「3 分钟前」） | 需要复数形式；英文有复数，中文没有，斯拉夫语系更多 |
| 日期与日分隔线（「今天」「昨天」「周三」「10 月 3 日」） | 相对词要翻译，绝对日期按 locale 格式化 |
| 文件大小 | 十进制（kB = 1000）还是二进制（KiB = 1024）——选一个并写明，不要在界面中途换 |
| 数字 | 千位分隔符、小数点用逗号还是句点 |
| 并列项连接（「A、B 和 C」） | 不是字符串拼接——连接词在每种语言里都不同 |

复数是那个陷阱：`"{n} replies"` 除了英文，几乎在每种语言里都会错。从一开始就用 ICU 式的复数类别。

## 5. 版式必须扛得住翻译

英文通常是这些语言里**最短**的：同一个标签在德语或俄语里常见长出 30–50%，而中文常常更短但更高（中日韩字形是全宽的）。

- 文字按钮不设固定宽度。标签上不写 `width: 120px`。
- 溢出用省略号截断，而不是把一个控件的标签折成两行。
- 绝不把字烘进图标或背景图里。
- 上线一屏之前，先用一个故意拉长的伪 locale 试版式——不要用第二种真实语言去试，那来得太晚。

## 6. 文字输入与纠正

- **中日韩输入要懂组字过程**：输入法组字（IME composing）期间按回车不能发出消息。原型已经在 `isComposing` 上做了拦截；那道拦截要留着。
- **断行**不同：中日韩在字符之间断（并且有一批字符不许出现在行首），拉丁文在空格处断。用平台的 `word-break` 能力，而不是只靠 `overflow-wrap: break-word`。
- **搜索**不是 `indexOf`：大小写折叠、变音符号折叠，而中日韩还要在「子串匹配」和「分词」之间做决定。先做子串匹配，并且明说它是子串匹配，而不是假装它是搜索。
- **联系人和房间的排序**必须懂 locale（拼音、笔画还是字母），或者被明确定义——不能拿名字直接 `Array.sort()`。

## 7. 无论如何保持英文的东西

- 标识符：id、文件键、协议名、日志行、代码。
- 仓库：提交、issue、pull request、代码注释。
- 用户永远读不到的内部机制（一条判定的标签、一个理由 token——这些要通过 locale 渲染出来显示，但按稳定值存储）。

判定里的 `reason` 是个好例子：存的是稳定 token（`not_addressed`、`someone_answering`、`someone_spoke_first`），通过 locale 渲染——绝不存成那句译好的话，否则用新语言去读旧数据就断了。两件事跟着来。判定的**形式不固定**——一个词、一个标签或一小段 JSON，所选模型稳定吐什么就用什么——所以这里不许假设 JSON 键名。以及 **seek 没有任何额度**：没有花费上限、没有每日计数、没有冷却，所以没有任何理由 token 可以命名其中任何一个。

## 8. 现在不做的

- **RTL 版式**（阿拉伯语、希伯来语）。版式是固定的四栏结构；需要 RTL 时，方向必须成为一等版式属性，而不是一个 CSS 补丁。延期，但记在这里，免得左右假设被埋在一百个地方。
- **内容的自动翻译**。见 §2——它要么是一次显式动作，要么不发生。
- **逐条消息的语言检测**。对 agent 的判断有意思（这个房间说的是我的语言吗？），v1 用不上。
