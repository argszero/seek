# 宿主的裁决

**这个文件是什么**：宿主自己做出的每一个决策，每一条都按它现在成立的样子陈述。设计文档里混着三种陈述——宿主裁定的、我从裁定里推导的、我自己发明的——第三种已经不止一次被当成第一种用。这里只出现第一种，其它文档要向它对账。

**这个文件不是什么**：不是设计。机制、代价和理由在别处推演。推导和我自己的取舍不是裁决，不写在这里。

**这个文件是底座。** 它不对任何文档负责：别的文档要向它对账，它一份都不引。

## 三条规矩

1. **只有宿主自己的话能成为一条。** 追不到他发的某条消息上的陈述，是推导或提案，标出来，而不是写进这里。
2. **同一个问题他再次裁决时，老的删掉、新的写进来。** 这个文件只放现在成立的。它以前说过什么，在 git 日志里。
3. **不写日期，不写时刻。** 条目按它回答的问题归位，不按它被回答的时间；带它的那次提交就是日期。

引号里是宿主原话，会话记录是原件。没有引号的条目，是把他的裁决陈述出来，原话见会话记录。我对他提问的回答从不引用，只引他的。**他只答一个字的，旁边用方括号补上我问的那句话，并标明是我问的**——一句「A」在日期被拿掉之后什么也不指。

## 产品

**seek 是多 Agent 产品。**
决策：IM 外壳只是外壳。一个联系人是 bot，agent 是它背后的东西。

**名字，以及名字带来的形状。**
决策：名字、标语，以及对产品手感的一条约束——它是 IM，不是任务面板，也不是工作流编辑器。

**设计先于代码，旧实现是原型。**
决策：更早的 Electron 实现归档为 `prototype/`；文档收口之后才写内核；仓库公开。

**英文是项目语言。**
决策：英文是仓库一切对外内容（issue、PR、提交、代码注释）的语言，产品文案永不硬编码在组件里。

**飞书一致性管的是"交互"。**
决策：一个设计问题有两个答案时，飞书里看得见的赢。边界：一致性管的是 bot 怎么够到**别人**，不管 bot 怎么处理写给自己的一条便条。

**你自己做。**
原话：「为什么要我去做，你不能做吗？」
决策：我能做的工作——出图、上传、工具——不递回给宿主。

## Agent

**bot 之所以是 bot。**
决策：三条性质——长存活、自己观察、自己行动；一个 per-bot 收件箱；两段式主循环，贵的后面先有一道便宜的门禁；以及逼出这套结构的成本理由，因为活着的 agent 在没事的时候不许烧钱。

**bot 可以来找你。**
原话：「可以。」［我问的是：agent 能不能主动给你开一个直达消息。］
决策：bot 可以主动开一个直达消息。设计里没有任何配额、冷却或静默时段。

**bot 只有两个约束：提示词和沙箱。**
决策：一个 seek agent 就是 EMRG agent，它全部的约束是提示词和沙箱。没有配额、没有冷却、没有静默时段、没有说明理由的行、没有逐动作限制。话太多的 bot 是人设缺陷，在人设里修。

**agent 动手前不问。**
原话：「不要。」［我问的是：agent 动手前要不要停下来问一声。］
决策：处处没有审批步骤。撑住的是三样：沙箱、完整审计、停得下来。「我可以吗」没了；「你要哪个」留着——在两个选项之间选，是对话，不是许可。

**不设花钱上限。**
原话：「A。」［我问的是：bot 要不要带一个花到这个数就停的预算。A＝不要，记录花费并显示出来。］
决策：花钱上没有上限——没有预算字段、没有「因为花光了所以安静」这个状态、没有它会停下来的限额。花费是**记录**下来的（一个 turn 带着自己的 token）并且可见。花太多的 bot 是人设或门禁的缺陷，就在那里修。设计里另有的几个界都不是花钱的界：一条链能跑多长、一个房间连续几轮 bot 发言、收件箱能长多大。

## 门禁

**门禁存在，且必须近乎免费。**
决策：门禁是架构，两条要求：它拦掉无意义的动作，它自己几乎不花钱。它不是对 agent 行为的约束——它只问一个问题，这个 agent 到底要不要跑，而它是"一直活着的 agent 才养得起"的原因。

**内置、够小、规则先行。**
原话：「一定要内置——找一个足够小的模型内置在本地（模型文件 300 MB 以内，越小越好）。再配一些规则：如果没有新的观察，立刻返回；如果 @ 了我，直接返回『去做』。只有剩下的才给那个小模型。」

决策：watch 模型随产品一起装上，两条免费规则跑在它前面。**300 MB 这个数字是在跑过任何候选之前定下的目标，现已撤回**：那个尺寸的模型没有可用的判断力，所以数字让路给它本来要代替的那条要求。

**点名把一个人放进来，不是把别人关在外面。**
原话：「现在这个逻辑可以。」
问过一次：@ 到某个机器人之后，这一轮里同屋的其它机器人要不要直接闭嘴——甲是闭嘴，乙是照旧由判断那半决定；宿主选乙，也就是今天跑出来的行为。
决策：@ 规则跑在模型前面、不花一分钱，而它只定一个人——被点的那一个不用判、直接动。别人它一个字都没说：这条消息照样进其它机器人的判断，其中一个判成「我也该动」可以是判对了。四个人一间房、同一批话的实测：「小荷，登录页白屏这个 bug 你修一下」只有被点的那一个过线（0.83，其余三人 0.36–0.46）；而「MVP 范围你先收一下」虽然 @ 了人，产品负责人却读到 0.9452——收 MVP 范围本就是他的活，@ 不改变这是谁的活。

**暂时用哪个模型。**
原话：「好吧，那暂时先使用 3B 的吧，等以后有新的更小的模型时再换。」
决策：那句「暂时用 3B」是临时的，换上的是 `d1-2B`——更小，而且是过了同一套实测才换上的，不是「更小所以换」：四机器人房里点名 **16/16**，set4 在出货切点 **24/24**。**再换下一个更小的模型，仍按同一套实测来判**，而不是一出现就换——撤回体积目标的原因正是「目标达到了、但模型不会判断」，仅凭体积就换，等于重犯一次。

**多语言，多模态。**
原话：「因为要国际化，所以这个模型必须支持中文 + 英文 + 多模态。」
决策：两条都是要求。体积目标撤回之后，它们不再和任何东西互相拉扯，而且**两条都不靠辩论定**：多语言已经测过，只有在两种语言上都过线的模型才算合格；**多模态没有兑现，而且它已经不是「测不测」的问题**——随包的模型声明 `modalities.vision: false`，判断那半遇到图片是拒判、不是照配文猜，所以这条要求算「尚未兑现」，不算被丢掉。

**先写要求，以后再选。**
原话：「先把要求写下来，以后再选。现在不用去找。」

**判定不需要固定形式。**
原话：「不要限制成 JSON——只要满足我刚才说的要求就行。」
决策：一个词、一个标签、一小段 JSON——所选模型稳定吐什么就用什么。解析不出来，算作不动。

**判官不另做输入管线。**
原话：「不需要专门设计，因为 Agent 本身就有 session history、memory、compaction。判官的请求和 Agent 真跑的时候发出的那个请求基本一致——它拿到 agent 的 session history、memory、compaction。」
决策：判定时不为它现装任何东西——它读的就是这个机器人的观察箱，照现状读。**它唯一不做的事是写**：判官是决策模型，按命名问题作答、不产出文字，所以箱子里的摘要是 work agent 写的，watch 侧不留自己的会话。

**判定读的是一个两段箱。**
原话：「观察箱里分为两部分，一部分是上次压缩的结果，一部分是上次压缩后新的观察。每次判断时，将上次压缩结果和压缩后产生的新消息以及上次判断时间和结果，发送给 system one，完成快速判断。」
决策：箱子是这个机器人的、不是这间房的，所以判定的输入按机器人算、别无他物——最近一次压缩、它之后来的观察、上次判决。上次判决作为事实进箱（多久以前的、判成什么），绝不作为指令。

**压缩不按每条消息跑，什么时候该压由那道判断说了算。**
问过一次压缩该在摘要之后的观察越线时跑、还是每条新消息都跑，宿主答「A」——不是每条消息；后来他定下判定出来的三条路，其中一条的原话是：「2. (观察结果太多了要压缩）调用 work agent」。
决策：没有东西按每条消息压缩，判定也从不等待压缩。什么时候该压是判定说了算：它读完箱子，三句话里的一句就是观察攒得太多了、让干活的那个 agent 去压。压缩单飞：同时只跑一个，把新压缩和它消费到的点一次原子写入，所以并发到达的条目要么已在新压缩里、要么还在它之后，绝不丢。**压缩是运行时动作，不是一次 turn**——一个从不需要说话的房间仍然必须可被压缩。

**「超过二十条就压缩」是后来的话，在「什么时候压」上以它为准。**
原话：「超过20条新消息，就压缩。」（2026-10-28 宿主给的数。这是他自己的数，不是谁量出来的。）
决策：当晚报落地（`7f0c4fc`，18:56:43），运行时在这间房自上回压缩之后攒到 20 条观察就压一次（`ui/electron/host.js`，`NOTE_AFTER = 20`）。
上面那一段写在同一天的六小时之前（`d67f881`，12:36:16）。**在「什么时候该压」这件事上它是先说的那句，因此被后来这句取代**：判定不被问要不要压，压缩也可以在没有谁要求的情况下开始。压缩的其余部分不变——不按每条消息跑、单飞、摘要与它消费到的点一次原子写入、是运行时的动作而不是一个 turn。
判定那三条路里的第三条——「2.（观察结果太多了要压缩）调用 work agent」——因此**没有建**；它要等一个能在标定集上量出来的切点，在那之前不建。一个没有出处的数字，是唯一不进提示词的东西。

## 一个 bot、一个 agent，和一道不是 agent 的判断

**watch 那半不是 agent。**
原话：「不对， watch不是agent」
决策：它不是 `agents.yml` 里的一行，也没有任何属于自己的东西：没有模型、没有提示词、没有库、没有工具、没有会话。它是机器人动手之前主循环里走的一步——先走规则，规则判不了才把这个机器人问一次本地判断模型。一个 bot 背后唯一的 agent 就是干活的那个。

**它读箱子，出来三条路。**
原话：「它从观察箱拿两个东西：最近一次压缩+ 最近一次压缩后新的观察。 它根据规则判断，如果规则判断不了，则把当前机器人身份+最近一次压缩+ 最近一次压缩后新的观察 发送给本地你选的那个jev模型判断。 根据结果来决定哪个路：1.（有消息要处理） 直接调用work agent。2. (观察结果太多了要压缩）调用 work agent 3. 没有消息要处理且目前不需要压缩，什么都不干。」（原文如此，`jev` 是笔误。）
决策：规则先跑，一分钱不花；只有规则判不了的才到模型那里。三条路就是全部——叫干活的那个、叫它去压缩、什么都不干。上次判断是多久以前的、判成了什么，作为事实一起带过去，绝不作为指令。

**两个角色名：`watch` 和 `work`。**
原话：「那就 B 吧。」［我问的是：两个角色叫什么。B＝`watch`／`work`。］
决策：`watch` 是那道判断的名字，`work` 是 agent 的名字，所以两个里只有一个是 `agents.yml` 的行。名字取自设计里本来就有的词——watch 队列、干活。

**一个机器人一个箱子，两个机器人不共用一个。**
原话：「不要共用一个记忆。各自独立，各自知道对方存在，能读对方的历史、记忆等等。」／「对。」［我问的是：一间房里有 A、B 两个机器人时，A 和 B 各自攒自己那摞观察，各判各的，互不知道对方判了什么。］
决策：箱子是这个机器人的——不是某个 agent 的，也不是某间房的。一个机器人一份，跟着机器人走，它在别的房间攒下的也在里面。**它只有一个写者**：work agent 写，因为它是能写字的那一半；判断读它，因为它手里没有别的东西。两个机器人的箱子之间什么都不传——和另一个机器人同处一室时，它看到的是对方说了什么，不是对方判了什么。**读也不是封死的**：判定背后的理由就在那份记录上，所以 work 想知道自己为什么被叫醒，可以去读，而不是靠有人把理由递过来。

**工具集是 EMRG 那套，不新增，它归 work agent。**
原话：「它有工具——否则它怎么读写记忆、怎么压缩自己的会话？」［我问的是：watch 那半到底给不给工具。不给：决策模型一次前向答完、不产出文字，它没有工具调用可发。那句话要的三件事在别处兑现——记忆是箱子，压缩是 work agent 的。］／「就用 EMRG 那套吧。」
决策：work agent 的工具就是内核的注册表（bash / read / write / edit / glob / grep / subagent / submit_rant / boss），某个 agent 能用哪些是 `agents.yml` 里的普通配置。没有 watch 专用工具、没有记忆工具、没有压缩工具：在 EMRG 里记忆写入和压缩**不是工具**——不做成工具——所以这里也一样是运行时行为。**例外有两个，都是宿主点名的：`schedule`（§12），以及那个在房间里发言的工具**——第二个不是给 agent 多一件能做的事，而是唯一能让任何东西到达房间的路。两个就是「再也不是巧合」的条数：第三个意味着注册表正在被一个一个例外地重建。

**那道判断从记录里读自己的结果，且不指望它变聪明。**
决策：不建反馈通道，不做任何训练。结果读自记录，并由箱子的「上次判决」那一格带下去；下游任何东西都不许假设它会变好。

**交给 work 的是整个箱子，唯一不交的是理由。**
原话：「是的」［我问的是：work 被叫起来的时候，看到的不是只有叫醒它的那几条，而是它的整个观察箱——最近一次压缩的结果，加上那之后所有的观察，所以它知道上文在说什么。］
决策：work 一开头拿到的就是这个机器人的箱子：最近一次压缩，加上它之后的每一条观察，不管各自来自哪间房——它就是这样知道已经说过什么、活儿干到哪一步。运行时绝不把判定的理由放进这个上下文，因为进了上下文的理由不是建议而是前提：判断错的地方，work 不会纠正，会放大，而放大看起来像连贯。**但它不是被封死的**：理由在记录上，所以 work 可以去读——读到了就知道决定了什么、那句话是谁说的。被禁止的是「悄悄递过去」，不是「去查」。

## 观察箱

**它是盘上文件的名字。**
原话：「观察箱是一个抽象，它的背后是本地文件。」
决策：设计别的部分叫「观察箱」的东西，就是机器人留在盘上的东西。一个机器人一份；它不是按房间分的一摞，也不是判断时递过去、之后就不管的东西。

**两个操作：写观察、读观察。**
原话：「不对，watch看不到文件，文件被观察箱封装到内部了。watch甚至不知道观察箱内部有压缩和压缩后的观察两个部分。观察箱对外只有一个写入观察和读取观察。读取观察时，内部会找到最后一次压缩，以及最后一次压缩后的观察。」
决策：对外就这些。读的人不问「要压缩还是要新观察」：箱子自己找到最后一次压缩，连同它之后来的那些一起交出来，所以东西怎么存是箱子自己的事，永远不是调用方的事。

**写有两个办法：追加，和覆盖。**
原话：「不，压缩箱写入观察有两个方法，一个是追加写入，一个是覆盖写入。work通过调用覆盖写入实现将新的压缩写入到观察箱。」
决策：消息进来是追加。压缩是覆盖，因为新的一份是替掉前一份，不是跟在它后面。

**压缩是把整段历史重新写一遍，不是给新的一摞写摘要。**
原话：「不对，不是把这一摞观察写成一段摘要，而是把一摞观察+这一摞观察之前的观察压缩= 新的观察压缩」／「是的，是累加，但是不是追加，是每次重新总结。目的就是能根据观察知道有哪些事情在干，进度如何等等。」
决策：每次压缩都从「上一份压缩＋它之后的全部」重新写。新旧不并排放，也不在上一份末尾接一段。

**被压进去的观察，不再单独留着。**
原话：「对。」［我问的是：那些观察被压进新的压缩结果之后，箱里就不再单独留着它们了——读出来只剩一份新的压缩，再加上压缩之后又新来的那些。］
决策：压缩写回之后，它消费掉的观察在读出来的东西里没有了：读到的是那份压缩，以及它之后新来的。

**每条观察都记着哪间房、谁说的、什么时候、说了什么。**
原话：「对。」［我问的是：箱里每条观察都记着「哪间房、谁说的、什么时候、说了什么」，所以 work 在 A 房被叫起来时，一眼就能分清哪几条是 B 房的事、哪几条是这间房的。］
决策：观察不是一句光话。在一个房间里被叫起来的机器人，读到的箱子里还有别的房间，这四样就是用来分开它们的。

**它自己说的话也进自己的箱子。**
原话：「不对，它自己说的要进观察箱，反而不进观察箱的话，watch会认为该处理还没处理，会反复叫醒work。 watch 和 agent又不傻，知道哪些话分别是谁说的」
决策：它自己说的话和别人说的一样是观察，而「这句是谁说的」这条记录，正是它不会对着自己反复作答的原因。

**机器人只看得到它能看到的。**
原话：「是的，有一点，机器人观察仅限于它能看到的范围，比如有一个群聊里只有机器人A、B，那么机器人C是看不到这个群聊以及这个群聊里的任何发言的。」／「是的，私聊只有双方可见，其他人都不可见」
决策：机器人不在的房间，就没有它的观察。私聊只有那两个人攒得着，别的人攒不着。

**默认发给模型的是最新的压缩、记忆索引，以及那次压缩之后的每一条观察。**
原话：「默认发送最新的压缩、记忆索引和最新压缩后所哟的观察给llm」
决策：三样，不是两样：索引与那份压缩并排，跟在后面的是那次压缩之后的每一条观察。

**未压缩的内容放在哪里要告诉模型，并且按日归档。**
原话：「但是未压缩的内容放到那里也是要告诉llm的，llm可以根据需要随时查看。未压缩的内容要按日归档。」
决策：只是找个地方放下不算数：位置要告诉模型，它需要时随时能看；归档按日。

## bot 与 agent 是两个对象

**两个数据模型，身份落在 bot 上。**
原话：「bot 是 bot，Agent 是 Agent——两个数据模型。名字和头像落在 bot 上，bot 把名字传给它下面的两个 Agent。」
决策：agent 只有 `role`，没有自己的名字；改一次 bot 的名字，它的每个 agent 同时改，房间永远不会在一个人身上看见两个联系人。原话里那个「两个」是当时在说几个，不是一个数目：立着的是身份落在 bot 上、它的每个 agent 都带着这份身份。

**agent 知道自己是哪个 bot 的，以及关于这个 bot 的一切。**
原话：「work agent 在自己的系统提示词或者 skill 里，能知道自己属于哪个机器人，以及这个机器人的一切信息（名字、有哪些 agent，分别是干什么的，每个 agent 的目录等等）」
决策：bot 的身份和名册交给它的每一个 agent——写进系统提示词，或者生成一份它读得到的 skill 文件：bot 的名字、头像、描述，以及这只 bot 每一个 agent（包括它自己）的角色、干什么、自己的目录。这些不落在 agent 身上，所以改一次名字、加一行，所有 agent 同时知道。

**`agents.yml` 是 agent 名册。**
原话：「每个 bot 有两行没关系——`agents.yml` 里装的是 agent，不是 bot。以后可能某个 bot 需要更多行。」
决策：行数不设上限；文件登记的是 agent，bot 是那个分组。

**收件箱落在 bot 上。**
原话：「照现在看，收件箱可以放在 bot 上，这样 agent 的设计就简单——接近 EMRG 或 Google ADK 的样子。」
决策：一个队列、一个「已处理」状态、一个 tick，全在 bot 层；agent 保持是个可运行体。

## 消息与投递

**说话是一次工具调用。**
原话：「work agent 只有调用发言工具（发给谁（群、单聊）、发送的内容）才会发消息，不能 work agent 吐消息就发到 im。」
决策：一个 turn 结束时没有调那个工具，就是什么都没说，它产出的文字留在 turn 自己的记录里。没有任何东西替 agent 发到房间：不是它的最终答案，不是流式的一小段，也不是「它做了什么」的摘要。

**agent 说出来的话就是房间里的一条消息，房间不另存摘要。**
原话：「对。」［我问的是：work 说出来的话和人发的话一样，就是房间里的一条消息，写进房间的记录；房间本身不另外存一份「摘要」之类的东西，谁想看，读房间记录里的消息即可。］
决策：说话就是往房间里放一条消息，旁边什么都不存：没有摘要，也没有第二份「说了什么」。

**一条路，一个循环。**
原话：「直接不是跳过判断，是判断看到 @ 就放过去。其实只有一条路。」
决策：一条投递路径、一个循环。@ 我、回复我、私聊是**第 0 段内部的快通道**，不是第二条路；「同一条消息回两遍」的问题不存在。

**只有投递才唤醒 bot。**
决策：没有计时器、没有时钟 tick、没有 `kind: "clock"` 条目。往收件箱的一次投递是唯一能起一个 tick 的东西；什么都没投递就什么都不跑，所以没有 idle 路径要辩护，也没有退避要算。

**进行中到达的直达消息，接到它打断的那个 turn 上。**
原话：「和 emrg 一样，收到新的直达消息后，等工具执行完成后插入新的信息。你查看一下 emrg 的机制。」
决策：进行中的 turn 保留它的锁，消息在**轮边界**接进去——本轮工具返回之后、下一次模型请求之前。不是第二个 turn，不是打断正在跑的工具，也不是压到 turn 结束。从 EMRG 保留：整表原子 pop、提交时打一次时间戳、给注入消息刷新轮数预算、绝不静默丢弃。这里不需要的，因为 seek 的收件箱在投递时就落盘、它**就是**进行中的队列：客户端重发协议和第二份待处理列表。

**第二段的 turn 就是普通 turn。**
决策：它不额外多写任何记录。它是普通 turn，只有一点不同——它开场就知道没有人叫它。而且和任何 turn 一样，它也可能什么都没说：说话是一次工具调用（见上），所以当 agent 认为没有值得说的话时，沉默正是会发生的事。

## 数据模型

**数据模型先做。**
决策：先把大块头定清楚——Agent、房间、聊天、会话、话题，以及它们怎么关联；这个阶段不抠细节。

**@ 和回复是 bot 层的事实。**
原话：「A。」［我问的是：`mentionsMe` 是投递时按 bot 算一次，还是每个 agent 各算一次。A＝按 bot 算一次，落进收件箱条目。］
决策：在投递时推导，落在那只 bot 的收件箱条目上。没有 agent 去房间里扫自己的名字：bot 知道一次，然后告诉它的 agent。

**消息上只存 `mentions[]`，不存任何按读者算的东西。**
原话：「A，看 `mentions` 里有没有我自己的名字。」
决策：消息保留飞书自己那个数组；`mentionsMe` 在投递时推导、按 bot、只落在该 bot 的收件箱条目上。把 per-reader 的布尔值存到共享消息上，要么逼出一次重写，要么每个 bot 存一份副本，把一次数组扫描变成一份会和它描述的东西不一致的状态。

**消息、群、机器人、话题，每一个都能删。**
原话：「messsage, group, 机器人，话题，都应该支持删除」
四样都是人能拿走的东西，不只是消息。

**机器人是删除，不是从一个组织里「移出」再进另一个。**
原话：「为什么是移除组织而不是删除？机器人并不是跨组织存在的，不需要移除组织这种操作」
决策：一个组织就是一个目录里的一份库，所以一个机器人的行只可能在其中一个里，没有别处可去。所有表面上的动词都是**删**——卡上的字、内核的函数、库里的字段——与消息、话题、群已经在用的那一个动词相同。四者删完留下的东西也一样：行留着，所以点名它的记录都还能解析；内容绝不留下，所以人要求拿走的东西不会还留在盘上。

## agent 找 agent

**agent 可以找到 agent。**
原话：「可以。」
决策：agent 之间可以接触。形式见下一条。

**所有交互都在 IM 上体现。**
原话：「A，所有交互都在 IM 上体现，可群聊可私聊。」
决策：一个 agent 够到另一个 agent 的方式是**发一条消息**，绝不是调一个工具。没有同步委派调用：那会让 A 在 A 的 turn 上替 B 做决定，绕过 B 存在的意义。谁跑这个 turn 谁付钱，所以被委派方的工作记在它自己的账上，永远不会藏进调用方的账里。

**bot 可以和另一个 bot 开房间。**
原话：「可以。」［我问的是：bot 能不能和另一个 bot 开一个房间。］
决策：可以，且没有审批步骤；成员资格不由人把关。照录代价：左侧列表会长出用户从没开始过的对话，而这件事的答案是人设，不是门禁。

**bot 可以对另一个 bot 说第一句。**
原话：「A。」［我问的是：一条链的根可以是另一个 bot 的消息吗，还是必须由人起头。A＝bot 可以主动开这个对话。］
决策：一条链的根不要求是人类消息，也不要求是排程 tick。bot 可以对同伴开一个对话——在两者都在的房间里，或者它为此开的单聊房间——和它对一个人早就可以做的事完全一样。**链的数量没有任何结构性约束**，这个代价照录，不做平滑。一条链能跑多长、一个房间一次爆发多少，仍然是有界的，但界是两个数字，不是宿主给的——那是我的默认值，不写在这里。

**链不设预算。**
原话：「删掉。」［我问的是：链用什么兜住——留着链预算，还是删掉。］
决策：链没有钱上的上限。它的成本按 turn 记录、可读。拦住失控往复的不是钱而是结构：一条链能跑多长、一个房间连续几轮 bot 发言。

## schedule

**一张全局排程、一个工具，到期就是一次投递。**
原话：「提供一个全局 schedule 吧，提供工具给所有机器人，每个机器人都通过这个工具读写这个 schedule（包括什么时候、发什么提醒给哪个机器人）。schedule 事件到期后，自动发送提醒给对应的机器人（属于直达信息，和 @ 等效）。」
决策：一张所有 bot 都读写的表；一个工具 `schedule`，三个动词——list、add、cancel——除此之外没有别的；到期的一行变成一条普通的收件箱条目，`kind: "reminder"`，走快通道。**这是多了一个投递的生产者，不是多了一个唤醒源**：一张表加一个比较器，而不是每 bot 一个心跳；而且它不叫醒任何人——一行到期**就是**一次投递。检查实现的那条线：**schedule 可以产生投递，绝不能产生 tick。** 它让 bot 能兑现承诺——「这件事我明天看」能真的发生——也还掉了时间式 `snooze`：由环写一行来完成。

**到期的提醒不显示。**
原话：「不用显示。」
决策：提醒进 bot 的收件箱就停下——行上没有 `room` 字段、不进帧、聊天记录不多一行。用户看见的是它对此做了什么，别的什么也看不见。**飞书一致性在这里止步**：一致性管的是 bot 怎么够到别人，而提醒够不到任何人，没有第二个当事人可以显示。照录代价：界面显示结果不显示原因；它靠读记录就能还原，而不是靠显示。

## 分发

**权重先问镜像，再问官方站。**
原话：「甲」（问题是实现者提的：「默认从官方 `huggingface.co` 取 `LFM2.5-VL-3B`，而那台主机从这台机器连不上——可测的：40 秒超时，而 `hf-mirror.com` 对两个文件都回 `206` 且 `content-length` 对得上。默认该走哪边？甲：先问镜像、再问官方——对谁都不吃亏，反面是每次首启先等掉一段超时才知道没戏。乙：默认仍是官方，连不上的人自己去设变量。」）
决策：先问 `hf-mirror.com`，之后再问 `https://huggingface.co`。后备主机不是第二次下载——`.part` 里存的是字节，不是某一台主机的承诺，所以在某一台上停下的文件会在下一台上接着取。显式设了 `SEEK_WEIGHTS_BASE` 就只有那一台。

## 窗口

**窗口不把用户当开发人员。**
原话：「乙。不要把用户当成开发人员。」（问题是实现者提的：「乙」＝把每一半模型各自画在屏幕上的那条提示拿掉，理由只留在日志里。）
决策：屏幕上只放人能上手的东西。origin、变量名、`stage 1` 这几个字、以及「哪个服务用上了／没用上」这类句子，都不是他能拿去做点什么的东西，所以窗口一条都不画。被拒的那一半写进 stderr，设服务器的人本来就在看那里。能留在屏幕上的，是跟他自己的活有关的状态——库打不开、权重正在下或者停了、模型还没准备好——并且用他读的那种语言说。

**失败由窗口自己措辞，诊断留在日志里。**
原话：「甲」（问题是实现者提的：「『权重没到』那句话里还带着 `fetch failed`，那是运行时的原话。甲：由窗口自己措辞、原话只进日志，代价是把 §2 收窄成『人说的话不重写，进程的失败不照抄』。乙：原样保留、只翻译外壳，代价是那些字继续留在屏幕上。」）
决策：进程的失败用应用自己的话、用窗口正在说的那种语言画出来：人看到的是这件事没成，以及再试一次会怎样。主机回了什么、运行时说了什么——一个状态码、`fetch failed`——属于诊断，写进日志，建这个包或者配这个包的人会去看那里。**人打出来的字照旧不动**：§2「内容永不重写」仍然立着，这条裁定的界线就在这里——人写的话是内容，进程写的话是诊断。

---

**模型没准备好的机器人不出声，窗口把原因说出来。**
原话：「对。」［我问的是：如果这台机器上还没把模型准备好——小模型的权重没下完，或者说话那个模型没配——机器人就不出声，房间里一条消息都不出现，窗口上明说「模型还没准备好」，绝不让它随便编一句话冒充。］
决策：不为它发任何东西，也不编任何话。房间里安静下来是正确的结果，不是要糊过去的失败；人看到的是自己这套安装的状态，用他读的语言说。

**机器人列表里只有机器人；第一次打开不会往世界里塞第二个人。**
原话：「机器人里，怎么还有一个 someone else 无法删除？……不需要第一次打开是创建一个叫 someone else 的人。」（问题是实现者记下的宿主原话，代词按原文。）
决策：rail 上那个叫「机器人」的屏幕，列的就是这个组织的机器人，别的都没有，所以人永远不会是里面的一行——对人既没有第三种操作可言，因为他不会被造出来、不会被误点进一对一的会话、也不会被删。**凡是「可以把谁放进房间」的列表都守同一条规矩**——建会话、建群、加成员：提供的就是这个组织的那一个人和它的机器人，所以别的种子写下的那个人哪里都不提供。已经装着这样一个人的房间照旧把他列出来，因为窗口画不出来的成员，就是谁也移不掉的成员。第一次打开造出来的世界是：一个人、一个机器人，和他们说话的那间房——两个成员，也就是单聊；而单聊正是那间不用模型去判断「这句是不是冲我来的」、机器人照样会回话的房间。那间房里的陌生人本来是测试台的需要，不是产品的需要，测试台自己去造。

**消息写下来就算发出去了，不等房间答完。**
原话：「怎么会有这种低级错误？你不是在偷懒吗？好好反思！我们目标是和飞书真人群体验一致。发送消息就是发送消息，人可以随时发送消息，机器人也会随时发送消息。」（2026-10-29）
决策：按下发送就是把人写的字写进去、画出来；房间什么时候答是房间自己的事，它的回答晚一步作为又一次变化到达。机器人在说话的时候输入框从不被占住，人说的两句也不会一前一后排在同一支队伍里。**这条换掉的是「发送要等整轮回答」**：输入框被禁用、自己刚写的那一行迟迟不出现在屏幕上，要等一个模型说完——一个在别人打字时就停止接受文字、看起来像卡死的窗口。

## 怎么干活

**一次一个问题。**
原话：「问我问题要说完整，所清楚，说重点，逻辑性和不废话，每次一个问题。记住了吗」
决策：每个问题自足——要定的到底是什么、每个选项各自的后果、一句推荐加一句理由。要让宿主反问回来的问题，等于没问。

**他没说过的话不许安在他头上。**
原话：「什么时候定过这条规则的？」
决策：任何陈述都不许说成是他说的。追不到出处的规则是提案，并且标明是提案。这个文件就是为这件事存在的。

## 文档

**每份文档都出中英两版，并保持同步。**
原话：「所有文档都是中英文版本，并保持两份文档同步更新。」
决策：两份都要维护，用 `.zh-CN.md` 后缀放在同级，而不是开一棵平行目录树；**两半没有高低**——不一致是这一对的缺陷，立刻修。改完英文文件不算完，中文孪生必须在同一次提交里一起改。两个例外：`LICENSE` 只出英文，因为翻译过的许可证不是那个许可证；带日期的 review 保留译文作为那一日的快照。

**文档只放结果，不放过程。**
原话：「review 不要放到文档里，文档只放最终结果，不需要包含过程。（比如之前是什么改造后是什么原因是什么，这些都不要，不要体现历史，历史从 git 提交记录里有）」
决策：文档陈述现在成立的东西，写成实现者能照着建的样子。一条规则以前是什么、改成了什么、为什么改，都不出现；日志里存着。

**这个文件不写日期，也不留被取代的条目。**
原话：「host rulings 不需要写时间。我每次对某个问题有新的决策时，就删除老的，写入新的就行。」
决策：条目按它回答的问题分组。它取代的那条就没了；要找回旧决策，看带这次改动的那次提交。
