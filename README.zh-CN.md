# seek

<img src="assets/icon.png" width="104" align="right" alt="seek：一枚装着瞳孔的气泡" />

> **I Seek You** —— IM 最初的原点。
> 打起来像 ICQ，长成你熟悉的那些角色的样子。

名字来自 ICQ 出发的那句话。二十多年前，即时通讯的意义是**去找一个人** —— 不是打开一个软件，不是启动一个任务，而是够到某一个具体的存在。

seek 保留这个原点，只把「人」换掉：你的联系人不再是真人，而是一群长期活着的 agent。它们有名字、有脾气、有自己的活。你在房间里说话；它们从旁边听着；它们觉得值得开口时开口，真有事情需要你拍板时来找你。

这不是飞书克隆。这是一个穿着 IM 外衣的多 Agent 产品。

## 状态

**内核已经有了，界面开了头。** 三份设计文档已经定稿（`docs/design/`），内核写在 `src/` 里（58 个 TypeScript 文件、约 22,125 行、413 个测试），上一版可运行的实现留作参考原型（`prototype/`）。界面是 `ui/` 下的独立包——Electron 在主进程里跑内核，渲染层是 React——它已经跑得起来：能打成可下载的 macOS 应用，而全新安装第一次打开时，它自己把要打开的世界造出来——一个房间、它的 bot，以及旁边的名册——此后从内核里读出房间、成员和消息画出来，接受你输入的消息，也能打开一条消息的线程。窗口也写，而且只经内核写：房间列表旁边的 `+` 造一个房间——一个名字，以及谁一开始就在里面——走内核自己的 `createRoom()`；房间标题里的成员数点开就是那份名单，按一下 `Add` 就把一个人加进去，走内核的 `addMember()`；两种拒绝都照内核自己那句话画在表单旁边。同一份名单也能把人移出去，走的是同一个 `removeMember()` 的另一头；房间自己的那一栏里，`Leave` 也是它——最后一个人会被拒绝，因为没人所在的房间再也不可能有人说话。退出之后，这个房间也从列表里消失——那一列画的是「我在的房间」，不是库里的所有房间，所以没有我的房间既读不到、也打不进字；而一句拒绝会把人和房间的名字说出来，不是那两个当键用的 id，因为窗口照内核原话画、从不改写。那一栏由成员数旁边那个标记打开，说的是这个房间是什么：名字、它是干什么的、群公告、标签、里面有谁、什么时候建的；没人写过的文字画成一句「写点什么」。`Edit` 经内核自己的 `updateRoom()` 改那四段文字——这是窗口第一次「改」，而且改得很窄：消息只记 `room_id`、从不复制房间名，所以改房间名不改写任何历史——名字空着会被拒绝，否则每个列表都退回去画房间的 id。这个房间也能删掉：同一栏里的 `删除这个群` 把房间和里面说过的话一起删掉，成员行也一起走，于是这个房间从每个列表里消失——这是「房间不能被清空」那条规矩唯一的出口，而且要先用一张卡问过，因为这个窗口里没有能反悔的东西。机器人可以在它自己的卡上被删掉：`删除这个机器人` 给它盖上戳、把它所有的成员行删掉，于是它不在任何房间、也不在这个组织「有谁」的名单里，而行本身留着——它写过的每条消息都还点着它，那个戳正是让这段历史还读得懂的东西。动词是删而不是「移出」，因为一个机器人只在**一个**组织里——一个组织就是一个目录里的一份库——没有别处可去；它先问一句再写，用的是另外三处删除同一张卡，因为这个窗口里没有能反悔的东西。机器人是在窗口里造的，不只是种子里那个：机器人列表旁边的 `Add bot` 收下一个机器人的四样东西——名字、性别、在这个组织里做什么、它怎么说话怎么做事——`Add` 把它们交给内核自己的 `createBot()`，它唯一的拒绝是「没有名字的机器人」，因为没有名字的机器人会在每份成员名单里被画成自己的 id。名字必填，另外三样不必：资料卡上还没写的，窗口画成「没说」，而不是留一片空白。同一次点击还把机器人需要的那两行名册写进库旁边的 `agents.yml`——那份文件**就是**名册，每次打开都读，而一个没有 `work` 行的机器人根本无法答话——而且是追加不是重写，所以人手工改过的行还在；行里用 id 而不是名字点名机器人，因为两个机器人可以同名，认不出谁是谁的名册会整份被拒。库旁边**根本没有**这份 `agents.yml` 时，库保留它已经有的那些 agent，也不会有人替它造一份——于是新造的机器人暂时不会说话，窗口就照实说这一句；而文件在、里面却一行没有，说的是这个机器人没有 agent。一条消息会点名它说的是谁——开放平台的 `mentions[]`，也是库里唯一记住「点了谁」的形式——窗口把那几个名字画在正文下面。图片比名字更进一步：它不是打出来的，是挑出来的；字节写到库旁边的一个文件里，消息本身只带一个指向它的 `{key, mime}` 引用——而且恰好在这条消息是图片时才带——所以一个有图片的房间是「一个库＋一个文件目录」，而不是一个把字节塞在里面的文件。消息经内核自己的 `deliver()` 落库，房间里的 bot 被收到的那条观察项叫醒，然后回应。要不要回应是模型的判断，回什么话是模型的文字，两段各自绑在自己的服务器上——你点名的 `llama-server`，或者包里带的那个，一次什么都不点名的启动会拿自己取回的权重把它起起来，写话那一段还可以是你配的通用端点；没有服务器在后面的那一段，才是内核自带的占位实现，窗口会说明每一段各站在哪一边。组织里都有谁，自己也占一个视图，就在房间旁边：每一行都写着它是机器人还是人，点开是一张卡，画的都是库里真有的字段——内核不存的东西一个也不画——`Message` 打开与那个人的会话：已经有只装着你们两个人的房间就进去，没有就经内核自己的 `createRoom()` 建一个。同样的房间还有第二个看法：群组视图列出成员不是恰好两个人的那些——这个内核里私聊是人数，不是一个模式——点开的一张卡写着它是什么、谁在群里，而建一个群走的是同一个 `createRoom()`，你自己已经在里面。线程也自己占一个视图：话题视图把整个库里的线程收在一处，不管它们起在哪个房间——线程就是内核自己的 `chain`，所以一条没人回过的消息不算——每一行写着它属于哪个房间、里面说了多少，点开就在它原来的房间里打开。线程同样是内核自己的记录，不是界面另开的一段对话：回复走同一个 `deliver()`，只是点名了它在回应哪条消息，面板画的就是库里已有的那条链。话题从它自己的卡上收走：卡上的 `删除话题` 把这条线程和它的回复一次删掉，因为缺了中间那一条的线程，就是一串答非所问。 一个窗口能装不止一个世界：设置页列出这台机器上的组织，`Create` 只凭一个名字就加一个，`Rename` 只改那个名字、不动世界里的任何东西，`Switch` 打开那个组织自己的库——不搬也不删任何文件——`Delete` 把那一行和它的目录一起移进废纸篓，正在看的那个和最后一个会被拒绝，因为总得有一个开着。名字只是列表上的标签，永远不是世界里那个人的名字：改组织名不改房间、不改消息、也不改「我」。

原型的存在只为证明一件事：这类桌面聊天界面可以被纯本地数据支撑。这件事成立。但它的数据模型是单人的 —— 一个账号、一群假人、消息属于会话 —— 那不是这一版需要的模型，所以它改造成不了这一版。

## 为什么不是又一个 IM 克隆

| | 飞书 / 微信 / Slack | seek |
|---|---|---|
| 头像背后 | 一个人 | 一个长期活着的 agent |
| 群里没人 @ 它 | 它永远不知道 | **它知道** —— 消息落进它的收件箱，零成本 |
| 它什么时候说话 | 只有被叫到时 | 它判断该说时才说 —— 用便宜的方式判断，不是每条消息都跑一次前沿模型 |
| 它的成本 | —— | **只记录，不设上限**——每一轮带着它读进和写出的 token，窗口把它们显示出来；不会因为花掉了就安静 |
| 上下文 | 完全共享 | **消息共享，上下文私有** —— 一个房间里五个 agent，不是五份房间 |


**按这个顺序读**：`docs/design/data-model.md` 定的是*有什么、彼此什么关系*；`docs/design/agent-lifecycle.md` 定的是*这些东西怎么活着、什么时候花钱*。想知道「谁在什么时候决定了什么、原话是什么」，读 `docs/host-rulings.md`。

**每份文档都有中英文两版，两份同步更新。** 中文版放在原文件旁边，用 `.zh-CN.md` 后缀（`README.zh-CN.md`、`docs/host-rulings.zh-CN.md`……）；两份一起改，两份不一致就是这一对的缺陷，而不是其中一份赢了。`LICENSE` 是例外，只保留英文 —— 翻译过的许可证不是许可证。见 `CONTRIBUTING.md`。

## 跑内核

**不用安装**：没有依赖，也没有构建步骤，克隆下来就能跑。需要 Node 22.18 或更新的版本 —— 代码是 TypeScript，类型由 Node 自己剥掉。

```bash
npm start                      # 第一个里程碑
npm start -- --lang zh-CN      # 同一次运行，中文
npm start -- seek-data/b.json  # 另一个存储，与自带的名册放在一起
```

它打印的是一个房间、一个人说了句没有点任何人名字的话，以及机器人有没有自己开口。**机器人的两半都还是占位实现** —— 要不要动的判断，和说出口的字 —— 报告里明写着这件事。一次运行展示的是内核：每个机器人一个收件箱的投递、闸门、回合。它展示不了的是这个设计立不立得住；那需要一个模型。

存储在 `seek-data/seek.json`，第二次运行会接着第一次建的房间往后写 —— 数据活过进程正是这个产品自己的论点，所以房间是变长而不是重置。想重来就把那个文件删掉。

想让实测过的观察模型替掉占位实现，就把这次运行指向**你自己起好**的 `llama-server`：

```bash
npm start -- --server http://127.0.0.1:8080 --window 24
```

`--server` 是一个 **seek 不启动、不监管、也不停止**的进程的 origin；`--window` 是一次判定最多能读多少 —— 那是调用方的数字，因为运行时并不知道模型的窗口有多大。两个必须一起给：只给一个会被拒绝，而不是靠猜补上另一半。**这个仓库不随包发任何权重**，所以这是这里唯一一条需要你自己提供东西的命令。

存储在 `seek-data/` 以外时，旁边要有名册。`agents.yml` 是每次开库时从存储自己所在的目录读的，库里的 agent 由它重建。**两种状态不是一种。** 旁边没有名册文件的库会保留它已经有的那些 agent——缺文件什么都不说，所以名册被删掉的安装照旧用原来的 worker 回话；而名册在、却一行没有，才是「这个 bot 没有 agent」的那句话。改这个文件是给 bot 换一套 worker 的办法，删掉它不是。真正拒绝的是 `npm start`：一个 bot 既没有 watch agent 也没有 work agent 的运行会停下来说清楚，而不是凭空造一个。

## 安装应用

[发布页](https://github.com/argszero/seek/releases)上是当前这一版，两种形状：`Seek-<version>-arm64-mac.pkg` 直接装进 `Applications`，`Seek-<version>-arm64-mac.zip` 是同一个包，解压后拖进去。Apple 芯片的 macOS。**`v0.1.1` 及更早**的发布是未签名构建的；从这棵树构建出来的包带有 `Developer ID` 证书签名并通过 Apple 公证，下面这一节讲的就是这件事。

**从现在起还会打一个安装包，和那个 zip 并列。** 在 `ui/` 里跑 `npm run dist:pkg`，会用 macOS 自己的 `pkgbuild`（`packaging/make-pkg.mjs`）从同一个 bundle 切出 `ui/release/Seek-<版本>-arm64-mac.pkg`；装它就把 `Seek.app` 放进 `Applications`，不必再拖。做成 `.pkg` 而不是 `.dmg`，是因为 electron-builder 的 `dmg` 目标最后要调 `hdiutil create`，而开发这个仓库的环境直接拒绝它（`the operation is not permitted`），`pkgbuild` 则不被拒绝——旁边的 EMRG 项目把 macOS 下载做成 `.pkg`，也是同一个原因。打包也不该是只有某台机器才做得到的事：推一个 `v*` 标签，会在 macOS runner 上跑同一条 `npm run dist:pkg`（`.github/workflows/release.yml`），把 `.pkg` 和 `.zip` 一起挂到发布页。

**从这棵树构建出来的包，装和开都不用先处理什么。** `release.yml` 从仓库 Secret 里取两张证书，导入一个只为这一次运行存在的钥匙串：`Developer ID Application` 给 bundle 签名，`Developer ID Installer` 给安装包签名（`packaging/make-pkg.mjs` 调 `productsign`，再用 `pkgutil --check-signature` 把链读回来核对），`packaging/notarize.mjs` 用 App Store Connect 的 API 密钥把安装包送交 Apple、等判决，把票据 stapling 到文件上，再让 Apple 把这张票据从文件里读回来核对一次。最后这两步都要连 Apple，所以那里的网络故障会被重试而不是被当成结论：已经写进文件的票据，不会因为某台主机连不上就不存在了。因此最后那次重读遇到 Apple 连不上时只报一条警告，只有包里确实没有票据才会让发布失败。这两张证书不能互换——安装包和 bundle 由系统里两个不同的部分来判定，`productsign` 会直接拒绝 Application 证书。本机上决定安装包签不签的是**安装包**那张身份：没有它时 `npm run dist:pkg` 照样能构建，只是明说这个包未签名、跳过 `productsign`，而不是失败。**bundle** 不是这样把关的——electron-builder 会自己在钥匙串里找到身份给它签名，所以机器上只要有证书（一张开发证书就够）就会签出一个带签名的 bundle；想让那台机器产出未签名的 bundle，用 `CSC_IDENTITY_AUTO_DISCOVERY=false`。发布流程从不依赖这种自动发现：`CSC_LINK` 明确指定 runner 用哪张证书。

**`v0.1.1` 及更早的发布会被拦，因为那些都还没签名。** 那些下载里没有签名、也没有公证，所以 Gatekeeper 会拒绝它。两种形状被拒的时刻不同，而 `.pkg` 在前：它在被打开时就受到评估，那时还没有任何 `Seek.app` 可以右键，所以属于「已装好的应用」的那条办法，选安装包的人照着做走不通。在已发布的 `v0.1.1` 那个 `.pkg` 上实测：`pkgutil --check-signature` 回答 `no signature`，`spctl -a -t install` 回答 `rejected`，理由是 `no usable signature`。下面这些是那些发布需要做的。

`.pkg` 要你把**下载下来的那个文件**上的标记清掉，然后再打开一次——或者在被拒之后的一小时内，进「系统设置 → 隐私与安全性」点**仍要打开**：

```bash
xattr -d com.apple.quarantine ~/Downloads/Seek-<版本>-arm64-mac.pkg
```

`.zip` 要动的则是应用本身：解压、把 `Seek.app` 拖进 `应用程序`，然后右键它选**打开**——或者清掉装好的那个包上的标记：

```bash
xattr -dr com.apple.quarantine /Applications/Seek.app
```

**签名之后，一个已签名的发布里还留着一处不对称。** Apple 给的票据是 stapling 到安装包上的，而 `.zip` 不是能贴上票据的东西：里面那个应用由同一张证书签名，但自己不带上票据，所以它第一次启动能不能过，取决于那台机器能不能连上 Apple。什么都不用处理的，是 `.pkg` 这一种形状。

**包里有什么、没有什么。** 内核在应用*里面*，不在旁边：`Contents/Resources/src/` 装的就是这个仓库自己的内核（`v0.1.3` 时是 26 个 TypeScript 文件，也就是所有不是测试的源文件），`Contents/Resources/app.asar` 装的是构建好的页面和主进程。**包里带着模型服务器，但不带模型。** `Contents/Resources/server/` 装的就是 `llama-server`——18,692,864 字节，被这个仓库自己跟踪，不是构建时现取的——而一次不点名任何服务器的启动，会拿首次启动取回的那两个权重文件把它起起来，所以早就不必自己点名一个 `llama-server` 了；你点了名，仍以你的为准。包里不带的是权重本身：它在首次启动时才到，所以第一次启动若断网，就一直是内核自带的占位句，直到权重到齐。**`v0.1.4` 是第一个带着它的下载**：`v0.1.3` 及之前的每个 tag 里 `ui/resources/server/` 都是空的，所以那些包只能靠你自己点名的服务器够到模型。**一个下载够不够得到这两段，取决于它是什么时候打的。** **`v0.1.0` 及更早**是接模型之前打的，那些包里只有占位句。`v0.1.1` 与 `v0.1.2` 的代码把两段都接上了，包里却仍然没有任何一段要读的工件——`prompts/` 与 `i18n/` 在那两个包里一个都没有——所以在它们上面点名服务器，得到的是内核自己那句拒绝，而不是回答。`v0.1.3` 是第一个带着它们的下载；用这棵树构建出来的包也带，靠的是下面那一节点名的那几个变量。首次启动造世界的方式也和下面那次运行一样——一个房间、它的 bot，以及库旁边的名册——而那个房间的 `created_at` 是内核的种子常量，不是你安装的那一刻，只是目前没有任何地方把它画出来。

应用把数据放在 Electron 自己给这个应用的 user-data 目录里，`SEEK_DATA_DIR` 可以指到别处。

## 跑界面

```bash
cd ui
npm install     # 只有第一次需要
npm run build
npm start
```

改页面本身的时候用 `npm run dev`：Vite 带着热更新把 `index.html` 服起来，再把 `SEEK_UI_DEV_URL` 设成那个服务器的地址——`http://localhost:5173`，也就是 `ui/vite.config.mjs` 不写端口时 Vite 自己用的那个——窗口打开的就是服出来的那一页，而不是构建好的那一页，于是改一行不必 `npm run build` 也能看见。

一个压在同一个内核上的 Electron 窗口：选一个房间，或者自己造一个——列表旁边的 `+` 收一个名字、勾上谁一开始就在里面，`Create` 把它交给内核的 `createRoom()`，空房间之类的拒绝就照内核那句话落在表单旁边；房间标题里的成员数点开是「谁在这个房间里」，每个还不在里面的人旁边都是一个 `Add`，按下去就是内核的 `addMember()`。然后打字、按回车，那个房间里的 bot 就会回应。点名是对这条消息的一个选择，不是正文里的字符：输入框旁边的 `@` 打开房间成员，一个字都没打也能先点名，之后打的字也还带着它。消息存下它点的人，窗口把名字画在正文下面，每个 bot 从那份名单里读出自己的 id——所以点名就是把一条消息递给某个 bot 的方式。它是判断第一段里的**快通道**，不是绕过判断的第二条路：判断看见了那个 `@`，就放它过去（`docs/host-rulings.md`）。图片不是打的，是挑的：输入框旁边的 `Picture` 按钮打开文件对话框，挑中的东西连同框里的文字一起发出去——框可以是空的，因为文字消息必须有字，图片的说明却可有可无。字节在**命名它的那条消息之前**就写到库旁边的文件里，因为 `deliver()` 会拒绝一个引用指向空处的 `image`；消息本身只带一个 `{key, mime}` 引用、从不带字节，而且恰好在该消息 `kind` 是 `image` 时才带——库每次保存都整片重写，塞进去的图会被每一轮无关的回合重新序列化一遍。窗口也只凭那个引用把图画回来，所以一个被搬走却没带上`media/` 目录的库会说「这张图不在了」，而不是画成一张空图。它能发的是个封闭集合——`png`、`jpeg`、`gif`、`webp`——类型是看扩展名得来的，因为文件对话框只给名字不给类型；认不出类型的文件是输入框里的一句话，不是一次猜测；对话框按了取消就什么都不用画。 输入框现在箭头旁边有四格而不是两格，图片旁边那两格都是客户端自己的。**笑脸把表情放进正在写的字里**，插在光标处——它是句子里的一个字符，不是划过消息时那条工具栏写进库的反应；反应是 `emoji_type`，一个按它数人数量的名字，而这个是文字。**加号收一个附件**，走另一次调用，因为文件是另一种类型：`⊕` 打开一个收任何文件的对话框，最大 25 MB，字节按应用自己编的键复制到库旁边，消息里留下的是这个人自己给的名字、大小和类型。按类型一概不拒——附件是交给这台机器上某个应用打开的，不是在列里画的——写着名字和大小那一行本身就是一个按钮：按下去把文件按原来的名字复制出来，交给系统自己的打开方式，所以一个被搬走却没带上 `media/` 目录的库会说这个文件不在了，而不是打开一个空文件。**要不要回应**是第一段，只要有一个服务器在用，它就是真模型——你自己点名的那个，或者你什么都没点名时应用自己起的那个：把 `SEEK_SERVER` 指向一个跑着的 `llama-server`，`SEEK_WINDOW` 写一次判断能读多少，判断就来自 watch 模型——由内核自己的 `watch-server.ts` 绑在那个服务器上，问的是 `src/prompts/watch-v1.json` 声明的那道题——于是它在自己判断该说话时才说，而不是每条都回。服务器要凭据的，由 `SEEK_API_KEY` 给，每个请求都以 `Authorization: Bearer …` 带上——`/props` 也一样——它属于这个 origin 而不是某一段，所以两段指向同一个服务器时带的是同一把 key；变量设成空的就等于没有凭据，而不是一个空的 `Bearer`，因为那样挣来的 401 读起来像 key 错了、而不是像没给。两个都不设时，应用会把包里带的 `llama-server`（连同首次启动取回的权重）起起来，并把两段都绑在这同一个 origin 上；只有当根本没有服务器在用时——你点名的那个被拒了，或者下载没下完——判断才是内核自带的占位实现，窗口不说你现在看的是哪一种——origin 和变量名都不是人能上手的东西，被拒的那一段只写进 stderr（`docs/host-rulings.md`）。**回什么**是第二段，而且是另一个服务器：把 `SEEK_WORK_SERVER` 指向另一个 `llama-server`，那句话就是模型自己的文字，经由 `src/prompts/work-v2.json` 给它的 `say` 调用说出来，而它的部件还会引一遍「加一个机器人时人填的那张卡」——它在自己的组织里做什么、它怎么说话做事，卡上写了才说——所以名册的 **work** 行必须声称那个服务器在服务的模型，因为一个服务器只服务一个模型，而两行可以各自点名。那个服务器不必是 `llama-server`：OpenAI 兼容的通用端点收的是同一个对话调用，所以把 `SEEK_WORK_SERVER` 指向你从服务商那里拿到的 `base_url`，再用 `SEEK_WORK_MODEL` 写出它的模型名，那句话就是那个模型的文字。写出模型名这件事本身就是「这是通用端点」的标记，因为它是这种端点唯一答得上来的东西——没有 `/props` 可问，所以第一轮之前要核对的只有一条：它自己的 `GET /v1/models` 里有没有你给的这个名字；名单里没有就是启动时的一句话，而不是一个下午都失败的回合。**提示词就是在这里离开这台机器的，也是唯一离开的地方**：库在本地、判断在本地，一轮要说的话在这里从库里拼出来，然后发给你配的那个服务器。不设 `SEEK_WORK_MODEL`，这一段就还是 `llama-server`；只设它、不设 `SEEK_WORK_SERVER`，这一段会拒绝而不是猜，因为模型名是某个服务器的事实。**而下载下来的应用不开终端也能用上那个端点**：双击启动设不了环境变量，所以这三样一个都没设时，说话那半读的是这台机器上**已经配好**的那个端点——`~/.emrg/config.toml` 的 `[llm]` 表里的 `base_url`、`api_key` 和 `model`，也就是宿主自己的 agent 运行时用的那份配置。环境变量只要说了话就赢，任何两个来源都不混合；`[llm]` 只写了三样里的一部分时，是一句话的拒绝而不是用一半——那句话点名缺了哪个键，从不带上凭据的值。**而这些现在窗口自己就能说了**：左下角那颗齿轮打开设置页，设置页把说话那半写进应用自己的 `settings.json`——就在 `seek-data/` 旁边，权限 0600，`SEEK_SETTINGS_FILE` 可以把它指到别处——于是这个端点是在应用里选的，不是在别的程序的配置文件里、也不是在一个双击设不了的变量里。轨道底部还放着一个月亮和太阳：按一下就让窗口在样式表本来就带着的两套配色之间换，选的那套存进同一个 `settings.json`，所以下一次启动直接就是它，而不是先画浅色再改。三个来源按一个人会期待的顺序读：环境变量，然后 `settings.json`，最后 `~/.emrg/config.toml`。每一份都整份用、任何两份都不混合，所以只写了地址没写模型的设置文件，是一句它自己的拒绝，而不是拿隔壁的配置补上。存下的端点在下一轮就生效，不用重启应用：宿主绕着它重开一遍，而判断那半不重启，因为它是一个应用已经起起来的服务器。只存了地址、没有存 key 的端点，是一个完整的端点，因为这台机器上的模型不需要 key；而 key 永远不会被画回页面里，页面只知道存了一个、它的后四位和它的长度。点名这个端点不会挪动判断：判断仍然在包里带的那个模型上，因为它读的是 token 概率，而通用端点报的是文字。不设的话，而应用自己的服务器又跑着，那句话就来自同一个 origin；`src/main.ts` 里 `stubDecide` 的那句话，是根本没有服务器在用时才说的。两段各要一个 origin 是刻意的，而 `SEEK_WINDOW` 仍跟着 `SEEK_SERVER`，因为它是「一次判断能读多少」，而一轮 turn 的提示词是每轮拿 work 服务器自己的窗口重新校验的。两段各自独立拒绝，所以 watch 行有服务器、work 行没有的库照样打开，用占位实现回话。你点名了、应用却没有用上的服务器（连不上、服务的是另一个模型、或者只给了不成对的一个）不会挡住窗口打开：窗口不画它，原因只写进 stderr 一行——库在本地，里面的消息不依赖那个服务器。每条消息下面都有「reply in thread」：打开的面板就是库里已经记下的那条链，在面板里回复走的是同一个调用，只是点名了它在回应哪条消息。占位实现的回应仍然落在房间里而不是面板里，因为 `stubDecide` 说那句话时不点名它在回应什么；模型的回应则挂回叫醒它的那条消息，所以画在面板里。鼠标划过一条消息就露出它的工具条，尺寸照参考截图量出来：一个 26×26 的白方块放表情，隔 2px 是一条 26 高的白药丸，里面四格各 24 宽——回复、转发、话题、更多——格间一道 1px 细线；它贴的是这条消息正文自己的右沿，不是整列的行尾，所以每段正文右边都留出一条位置给它。五个按钮，每一个都真的做事。表情那一格给出那个人可以挑的六个，按下的那个走内核自己的 `toggleReaction()` 落库，一次调用两个方向——再按同一个表情就是撤销——所以库里存的是 `operators[]` 而不是一个计数，图标旁的数字是那份名单的长度，底色表示这个人自己在里面。回复把一条消息放进你下一条要说的话里当引用：`deliver()` 在发出去那一刻把被引人的名字和头 160 个字取成快照，回复把这一块画在自己正文上面，所以即使被回复的那条后来没了，这条回复仍引着它当时的样子。转发把一条消息的原话、类型和图片从库里那份原件复制到**另一个**房间去——这次调用同时点名原件所在的房间和那条消息本身，因为转发的意思就是把它送到别处——转发出来的那条会写明这是谁的话。话题那一格打开库里本来就记着的那个面板。`更多` 里放的是这一版的两个平台动作之一 `Copy text`，它从主进程写剪贴板，因为页面自己那次复制要等一个用户手势：原型上脚本按一下报的是失败，人手按一下才成。另一个是消息自己菜单里的 `Delete`，它把字拿走，这个房间里的人就都看不到了，而行还留在原处、写着已删除——一条观察、回复的 `chain` 和一次 turn 都点着这个 id，挖个洞会让它们全指向不存在的东西——它带的图片或附件连字节一起删掉，还没发生的读也一并作废。第一次启动时还没有库，于是它自己造一个：内核自带的那个房间、一个叫 Echo 的 bot——它的资料卡是填好的而不是空的：`男`、`研发`、实事求是、老实听话，宿主自己的话，照原样存，因为 bot 的资料卡是内容，没有词典去翻译它——以及写在库旁边的 `agents.yml`——里面是这个 bot 说话要用的那两个 agent。所以窗口一打开就是能说话的地方，而不是一张空列表，那个文件此后也一直留在那里等着被改。它打开 Electron 自己的用户数据目录下的 `seek-data/seek.json`，用 `SEEK_DATA_DIR` 可以指到别处——想把仓库里的 `seek-data/`（连名册一起）打开，就是这么指。`npm run dist:mac` 构建的就是这个仓库发布的应用：electron-builder 把页面和主进程打成一个 arm64 应用包，放在 `ui/release/` 下；机器上有 `Developer ID Application` 身份就签名，没有就留成未签名。

**找不到权重的那次启动会去取，并且说着取到哪儿了。** 应用带着模型服务器，但不带模型：首次启动会把 `LiquidAI/LFM2.5-VL-3B-GGUF` 两个文件（共 2.2 GB）取到 `~/Library/Application Support/Seek/weights/`，期间房间上方的一条常驻条显示 `1.2 GB of 2.2 GB — <文件名>`。中途停下的下载会把已到的字节留在 `<name>.part`，下一次启动接着取，所以半路合上盖子损失的是这个文件剩下的部分，而不是整份重来。主机是按定下的顺序试的：先镜像 `https://hf-mirror.com`，再官方 `https://huggingface.co`，因为官方站并非所有网络都连得上——实测它在镜像能答的地方直接超时，而先问官方的顺序会让每一次首启都先付掉那段超时。在某一台上停下的下载会带着它已经拿到的字节接着取，所以后备主机并不是第二次下载。`SEEK_WEIGHTS_BASE` 指定一台主机、而且只有那一台；把它设成空值会被拒绝，而不是悄悄换回某个默认值。断网或者字节不够时，房间上方那条常驻条会说权重没取回来、点了哪几台主机、以及再启动一次会从盘上已有的字节接着下——每台主机各自回了什么只写进 stderr，不写到屏幕上，因为一个状态码和 `fetch failed` 是诊断，不是人能拿去做点什么的东西（`docs/host-rulings.md`）。

## 跑原型

```bash
cd prototype
npm install     # 只有第一次需要
npm start
```

一个 Electron 桌面客户端，四栏桌面聊天布局：消息、话题、联系人、群组和账号。所有东西都存在本地（`~/Library/Application Support/Seek/seek-data/`），包括图片和文件附件。见 `prototype/README.md`。

## 两块地基

1. **消息是共享的事实，上下文是私有的解读。** 一个房间只有一份消息记录，但每个 agent 有自己的视角、记忆和花费。
2. **省下的钱发生在第一段。** 每一轮，agent 先用零成本规则和一次廉价判断决定要不要动作；只有判断为要，才进入真正的 agent 循环。不花钱的那一段，才是「永远活着」这件事付得起的原因。

## 资产

标志是一枚装着瞳孔的气泡 —— 它在说话，也在观察。`assets/icon.svg` 是唯一源文件；`node assets/render-icons.js` 从它重新生成全部 PNG。那个脚本除 Node 之外什么都不需要：它逐采样点判定图形、自己写出 PNG，因为图标足够简单，引入一个光栅化依赖的成本比省下的更多。

`assets/social-card.html` 是 1280×640 的链接预览图；`assets/render-social-card.js` 用原型自带的 Electron 二进制把它截成 PNG，因为文字排版是纯 Node 唯一做不了的事。
